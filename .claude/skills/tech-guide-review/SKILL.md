# tech-guide-review — 기술 가이드 검증 체크리스트

## 검증 철학
단순 오탈자 교정이 아니라 **경계면 교차 비교**가 핵심이다. 각 문서는 맞아 보여도, 문서 사이의 가정이 어긋나면 학습자는 3단계에서 막힌다. 문서를 "따로" 보지 말고 "이어서" 본다.

## 파일별 체크리스트

### A. 기술 정확성
- [ ] 개념·수식이 맞는가 (예: `q = round(x/s) + z`, dequant `x̂ = s·(q−z)`)
- [ ] op 지원/미지원 서술이 벤더 릴리스 노트와 일치하는가
- [ ] "권장/주의/금지" 분류가 근거 있는가

### B. 명령어·코드 유효성
- [ ] 패키지명·플래그가 실재하는가 (예: `trtexec --int8 --fp16 --best`)
- [ ] Ubuntu 22.04에서 실행 가능한가 (배포판·아키텍처 전제)
- [ ] 코드가 import 누락·오타 없이 최소 실행 가능한가
- [ ] `sudo`, 경로, 환경변수가 명시됐는가

### C. 버전·링크
- [ ] 버전이 2026-07 기준으로 유효하고 시점이 병기됐는가
- [ ] 링크가 추측이 아니라 실재 URL인가 (의심되면 웹 확인)
- [ ] deprecated 도구를 현재형으로 쓰고 있지 않은가 (예: TFLite→LiteRT)

### D. 문서 간 일관성 (교차 비교 — 가장 중요)
- [ ] CUDA/드라이버 버전(01) ↔ TensorRT 요구 버전(05) 호환
- [ ] `layer_sensitivity.csv`(03) ↔ mixed precision 입력(05, 08) 연결
- [ ] `onnx_export_failures.md`(04) ↔ 캡스톤(08) 산출물 연결
- [ ] 상호참조 링크의 파일명이 파일명 맵과 일치하고 실재하는가
- [ ] 용어 표기 통일 (예: "캘리브레이션" vs "calibration", "폴백" vs "fallback")

### E. 원본 HTML 충실도
- [ ] HTML 각 단계의 핵심 함정 경고가 누락되지 않았는가
- [ ] 산출물(Deliverables)이 HTML이 요구한 것과 일치하는가

## 심각도 등급
- 🔴 **치명**: 실행 불가·틀린 개념·깨진 상호참조 → **직접 수정**
- 🟡 **권장**: 버전 미표기·설명 부족 → 리포트에 수정안 제시
- 🟢 **정보**: 개선 아이디어 → 리포트에만 기록

## 출력
`_workspace/review_report.md`에 다음 형식:
```
## {파일명}
- 🔴 [줄N] 문제 → 조치(수정함/수정안)
- 🟡 ...
```
검증 불가한 항목은 삭제하지 말고 "검증 불가 — 저자 확인 요망"으로 남긴다.
