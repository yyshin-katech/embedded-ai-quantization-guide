# stage-guide-writing — 단계 가이드 작성 규약

## 목적
모든 단계 MD가 **동일한 뼈대·톤·포맷**을 갖도록 강제한다. 학습자가 "읽고 그대로 따라 하면 실제로 실행되는" 문서를 만든다.

## 공통 전제 (모든 문서 상단에 반영)
- 실행 환경: **Ubuntu 22.04 LTS + NVIDIA RTX GPU(dGPU) 데스크톱**, Docker 사용 가능.
- 대상 독자: 임베디드 AI 엔지니어 취업/스터디 준비자(양자화 개념은 어느 정도 아는 중급).
- 보드가 없어도 되는 부분과 보드가 필요한 부분을 명확히 구분한다.

## 필수 문서 구조 (이 순서 고정)
```
# {단계 번호}. {제목}
> 원본 가이드 매핑 · 예상 소요 · 선행 조건 (한 줄씩)

## 0) 이 단계에서 무엇을·왜 하는가        ← Why 먼저
## 1) 학습 목표 & 완료 체크리스트          ← 체크박스 목록
## 2) 배경 이론 / 개념 (해당 시)           ← 수식·표·다이어그램
## 3) 환경·도구 준비                       ← 설치 명령어(bash)
## 4) 단계별 실습                          ← 작업 + 명령어 + 코드 + 예상 출력
## 5) 예시 / 결과 해석                      ← 실제 예시 값, 비교표
## 6) 흔한 오류와 해결 (Troubleshooting)   ← 증상 → 원인 → 해결
## 7) 산출물(Deliverables)                 ← 이 단계가 남겨야 할 파일/문서
## 8) 참고 사이트 & 참고문헌                ← 링크 + 논문(arXiv)
## 9) 다음 단계                            ← 다음 문서로 링크
```
> 이론이 없는 단계는 2)를 생략 가능. 나머지는 유지.

## 포맷 규약
- **명령어**: ```` ```bash ```` 블록. 한 블록당 한 목적. 주석(`#`)으로 각 줄 설명. `sudo`·경로는 명시.
- **코드**: ```` ```python ```` 등 언어 태그 필수. 실행 가능한 최소 예제로.
- **버전**: 확인한 버전은 못 박고 `(2026-07 기준)` 병기. 미확인은 `> ⚠️ 확인 필요:`.
- **표**: 비교(precision/latency/op 지원 등)는 표로. 
- **콜아웃**: `> 💡 팁` / `> ⚠️ 주의` / `> 🔴 함정` 인용구 사용.
- **체크리스트**: `- [ ] 항목` (원본 HTML의 체크박스 항목을 실행 가능한 형태로 옮김).
- 분량: 한 문서 150~400줄 목표. 지나친 이론 나열보다 "실행 → 확인 → 해석"을 우선.

## 참고문헌 섹션 형식
- 사이트와 논문을 분리한 소제목(`### 공식 문서 / 도구`, `### 논문`)으로.
- 각 항목은 클릭 가능한 링크 + 한 줄 설명. 논문은 `저자(연도), *제목*, arXiv:ID`.
- 리서치는 `embedded-ai-research` 스킬의 출처 맵에서 시작하되 웹으로 최신 확인.

- 참고문헌이 실재하는 URL인가(추측 링크 금지)?
