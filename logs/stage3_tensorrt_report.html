3단계 TensorRT — 실측 검증 보고서

3단계 문서(05_tensorrt.md)는 전부 trtexec 명령으로 쓰여 있으나 정본 pip 스택엔 trtexec가 없다. 실제 RTX 3080 · TensorRT 10.16.1.11에서 polygraphy Python API로 동일 파이프라인을 완주했다. torchvision ResNet50으로 FP32/FP16/INT8 3점 지연·정확도를 재고, §2.2.1(1단계 ResNet18 ORT-EP 관측)을 직접 파서 5케이스 절제로 정밀화했으며, 실습3 implicit 캘리브레이터의 생존을 확인했다. 핵심: trtexec 부재 → polygraphy, 직접 파서엔 독립 하드 블로커 2개(INT32 bias DQ + zp≠0), 그와 별개 축의 빌더 커널 부재(stem), implicit은 살아있지만 deprecated.

문서 전제(trtexec·§2.2.1 단일 블로커·implicit 제거 여부)를 실측으로 검증·정밀화했다. 상세는 각 절.

① 헤드라인 정정 (trtexec 부재)정본 pip 휠 tensorrt-cu12엔 trtexec 실행파일이 없다(PATH null, find 0건). 문서의 모든 trtexec --onnx=... --int8는 그대로 실행 불가 → polygraphy 0.50.3(network_from_onnx_path + engine_from_network)로 동일 결과. modelopt.onnx는 [onnx] 선택 의존성(onnxslim) 누락으로 import 불가. (§2)
② 실습1 3점 재현ResNet50 배치1·eval 5,000장: FP32 1.6615ms → FP16 ×1.96 → INT8 ×2.12(top-1 −0.52%p, INT8 커널 74줄로 QDQ 융합 확인). (§3)
③ §2.2.1 정밀화 (경로 병기)1단계는 ORT-EP로 "하드 블로커 = zp≠0 하나"로 봤다. 직접 파서는 5케이스 절제 결과 INT32 bias DQ도 독립 블로커(대칭 zp=0인데도 거부). 반전 아닌 경로 병기 — ORT-EP가 파서 전 bias DQ를 흡수하기 때문. (§4)
④ 빌더 vs 파서는 별개 축stem conv1(3ch 7×7 융합)을 INT8로 넣으면 파서는 통과, 빌더가 실패(Error Code 10, INT8 tactic 부재). 처방 nodes_to_exclude=["/conv1/Conv"]. (§4-D)
⑤ 실습3 implicit 생존IInt8EntropyCalibrator2가 TRT 10.16에서 여전히 빌드(deprecation 경고 Python 134건, TRT 로그 0). 이 모델에선 explicit보다 빠르고(0.707ms) 정확(76.80%) — TRT가 층별 정밀도를 자동 선택. 단 deprecated라 신규는 explicit 권장. (§5)
⑥ 범위 밖 (정직한 폴백)실습5 DLA는 num_DLA_cores=0(RTX 3080 dGPU) → 하드웨어 부재. Jetson Orin 전용. 실습6 플러그인은 헤비, 미실행. (§2·§6)
캐비앗(먼저) 절대 지연·top-1은 CUDA/RTX 3080 · polygraphy 빌드 · 배치1 기준이고, top-1은 5,000장 서브셋이라 공개값(76.13%)보다 부풀려진다(1단계 함정 0). 1:1 절대 비교가 아니라 같은 경로 안의 상대 관계(FP16/INT8 배수, implicit↔explicit 격차, 파서/빌더 절제 판정)가 유효 결론이다.

§3 — 실습1: FP32 / FP16 / INT8 3점 (ResNet50 · t02)

문서 실습1의 trtexec --fp16 / --int8 3점을 polygraphy로 재현. 배치1(지연 정본 지표), 300 iters(warmup 80), 정확도는 ImageNet val 5,000장. INT8은 explicit QDQ(ORT quantize_static, 대칭 QInt8·QuantizeBias=False·stem 제외 — §4의 정본 처방)로 만들어 파서가 그대로 먹는다.

재현 ✓ INT8 ×2.12 · 정확도 −0.52%p · QDQ 융합 확인

FP16은 top-1 완전 동일(76.88%)에 ×1.96로 사실상 공짜. INT8은 ×2.12에 −0.52%p(76.36%)이고, 엔진 레이어에 INT8 커널이 74줄 잡혀 Q/DQ가 실제 INT8 GEMM으로 융합됐음을 확인. 지연 최저는 §5의 implicit(0.7074ms/×2.35)인데, 이는 TRT가 지연 최소화로 층별 정밀도를 자동 선택한 결과다(§5).

주의 순수 INT8은 stem 융합블록의 커널 부재로 빌드 실패(§4-D)라, 실전 배포 구성인 INT8+FP16 폴백(int8=True, fp16=True = trtexec --int8 --fp16)으로 측정했다. top-1 서브셋 76.88%는 공개 76.13%보다 부풀려짐(함정 0) — 논점은 배수와 정확도 순위이지 절대값이 아니다.

(1) zp≠0(C·E) — §2.2.1과 일치, 경로 무관. (2) INT32 bias DQ(B) — 대칭 zp=0인데도 파서가 독립 거부. §2.2.1이 "2차 증상"으로 본 것과 다르다. (3) stem 커널 부재(D) — 파서 통과·빌더 실패, QDQ 제약과 완전히 별개 축. 정본 처방은 A: 대칭 QInt8 + QuantizeBias=False + stem 제외 + INT8/FP16 병용.

경로 병기 (반전 아님) §2.2.1은 ORT TensorRT-EP 경로에서 "zp≠0 하나, bias는 2차 증상"을 정당하게 측정했다. 여기(B)선 대칭인데도 bias INT32가 파서를 막는다. 차이는 모델이 아니라 경로다: ORT-EP는 파서에 넘기기 전 자체 그래프 최적화로 INT32 bias DQ를 흡수/제거해 파서가 홀로 선 INT32 DQ를 아예 못 본다. 직접 파서(polygraphy/trtexec/ModelOpt→엔진)는 원본 그래프를 그대로 파싱해 dtype 검사(only activation datatypes allowed, 모델 독립)에 걸린다. 따라서 §2.2.1의 결론은 ORT-EP 경로에서 유효하고, 직접 파서 경로에선 QuantizeBias=False가 필수로 강화된다 — 삭제·반전이 아닌 가법적 정밀화.

§5 — 실습3: implicit 캘리브레이터 생존 (t04)

문서 §2.2/실습3은 implicit(IInt8EntropyCalibrator2)을 "10.1 deprecated, 정본 10.16에선 살아있음"으로 서술한다. QDQ 없는 FP32 ONNX + polygraphy Calibrator(BaseClass=trt.IInt8EntropyCalibrator2)로 INT8 엔진을 실제로 빌드해 확인.

빌드 결과build_ok=True — 63.8초, 캘리브 캐시 5,776B 기록. TRT 10.16에서 implicit 경로가 여전히 동작.
deprecation 경고Python 레벨 134건 — 그중 "Superseded by explicit quantization"(= TensorRT 10.1 표시) 8건이 캘리브레이터 자체의 deprecation. 나머지 126건은 int8/fp16 config 플래그의 strong-typing deprecation(10.12). TRT 로그엔 0건(경고는 Python 바인딩 레벨).

확인 ✓ implicit은 살아있다 — 이 모델에선 더 빠르고 정확

implicit이 explicit보다 빠르고(0.7074 < 0.7843) 정확한(76.80 > 76.36) 건, TRT가 지연 최소화로 층별 정밀도를 자동 선택해 INT8을 57층만 쓰고 나머지를 FP16에 남겼기 때문이다. explicit QDQ는 감싼 층을 전부 INT8로 강제한다. 즉 이 결과는 implicit이 "더 낫다"가 아니라 제어를 TRT에 넘겼더니 이 모델에서 우연히 유리하게 떨어진 것이다.

그래도 explicit 권장 implicit은 10.1에서 deprecated(explicit quantization으로 대체) — 제어성이 낮고(층별 정밀도 보장 불가) 장기적으로 제거 대상이다. 위 유리한 수치는 모델 특이적이라 일반화 금지. 신규 파이프라인은 explicit QDQ(1단계 §2.2.1 정본 처방)를 쓰고, 지연이 급하면 int8+fp16 병용으로 TRT가 층별로 고르게 하되 QDQ로 임계층을 고정하는 게 안전하다.

§6 — 판정 & 산출물

정정 ✓ trtexec 부재 → polygraphy Python API

문서 전체가 trtexec 명령이나 정본 pip 스택엔 trtexec가 없다. polygraphy 0.50.3로 동일 3점·절제·implicit을 완주. 문서 §3에 부재 경고 + polygraphy 대체 경로를 반영.

정밀화 ✓ §2.2.1은 경로 병기로 강화

직접 파서엔 zp≠0 + INT32 bias DQ 두 독립 블로커(+별개 축의 stem 빌더 제약). ORT-EP 단일 블로커 결론은 그 경로에서 유효 — 반전 아닌 가법적 정밀화.

확인 ✓ implicit 생존 + 범위 밖 정직화

implicit 캘리브 TRT 10.16 생존(단 deprecated). DLA는 num_DLA_cores=0으로 하드웨어 범위 밖 명시.
