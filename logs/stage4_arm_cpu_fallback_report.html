ARM Cortex-A 폴백 — 실측 검증 보고서

4단계(멀티 SoC)의 벤더 NPU(TIDL/QNN/DRP-AI)는 보드가 없어 보류 중이다. 하지만 그 세 SoC가 공통으로 가진 ARM Cortex-A 폴백 경로(미지원 op가 떨어지는 그곳)는 오늘 측정할 수 있다 — Raspberry Pi 5(Cortex-A76)를 프록시로. 3·5단계 자산인 ResNet50 INT8 QDQ를 순수 CPUExecutionProvider로 관통시켜, 같은 INT8 그래프가 ISA에 따라 양자화 이득의 부호가 뒤집힌다는 것을 실측했다: Pi 5(dotprod)는 INT8이 ×1.83 빨라지고, x86 i9-10900K(VNNI 없음)는 되레 1.76× 느려진다.

원 질문("Pi CPU만으로 되는가?")은 확정: 된다 — GPU/NPU 없이 순수 CPU 경로로 완주·재현. 그리고 확인을 넘어, 4단계 벤더 SoC들이 공유하는 Cortex-A 폴백 바닥값을 처음 실측했다. 핵심 발견은 양자화 이득의 부호가 CPU ISA로 결정된다는 것이다.

발견 1 · 부호 반전같은 INT8 QDQ ONNX·같은 ONNX Runtime CPUExecutionProvider인데, Pi 5 Cortex-A76엔 asimddp(SDOT INT8 dot-product)가 있어 INT8이 ×1.83 빨라지고, i9-10900K(Comet Lake, VNNI 없음·AVX2까지)엔 dot-product 가속이 없어 양자화/역양자화 오버헤드가 이득을 잡아먹어 1.76× 느려진다. → "양자화 이득은 하드웨어 의존"의 깨끗한 실증.
발견 2 · INT8은 ISA 민감같은 1,000장·같은 CPUEP로 x86과 ARM의 예측을 1:1 대조: FP32는 1000/1000(100%) 완전 일치, 그러나 INT8은 958/1000(95.8%, 42장 상이). top-1 순증은 미미(x86 0.7530 / ARM 0.7500)하나 개별 예측은 ISA별 정수 누산·반올림 경로 차이로 4.2%가 뒤집힌다.
발견 3 · golden=TRT 전용5단계 커밋된 회귀 golden 테스트는 atol=1e-3이라 결정론적 TRT 수치 전용이다. 비결정 CPU wall-clock 행(Pi 145ms를 ±0.145ms로 재현 불가)을 results/에 넣으면 shape·허용오차 양쪽으로 깨진다(실측 확인) → CPU 프록시 4행은 bench/results/가 아니라 별도 cpu_proxy/로 격리.
캐비앗(먼저) Pi는 ARM Cortex-A 폴백 프록시일 뿐 자동차 NPU(QCS8550/RZ-V2H/TDA4VM)가 아니다 — 그 가속기 수치는 여기서 전이되지 않는다. 이 보고서가 측정한 건 "모든 op가 CPU로 폴백됐을 때의 바닥값"이다. 또한 절대 지연·top-1은 CPUEP · wall-clock 단일입력 · 배치1 · 1,000장 서브셋 · ORT 버전 상이(Pi 1.28.0 / x86 1.23.2) 기준이라 상대 관계(부호·배율·예측 일치율)만 유효하다. Pi↔x86 절대 속도 비교는 서로 다른 급의 기계라 논점이 아니다.

§3 — 부호 반전: INT8 이득은 CPU ISA가 결정한다 (핵심 발견)

아래 막대는 각 플랫폼을 자기 자신의 FP32 = 1.00×로 정규화한 상대 지연이다(절대 지연은 Pi가 x86보다 한 자릿수 이상 느리지만, 그건 서로 다른 급의 기계라 논점이 아니다). 세로 점선(1.0×)이 "자기 FP32" 기준선 — 왼쪽에 멈추면 INT8이 빠른 것, 넘어서면 느린 것이다.

왜 뒤집히나 ONNX Runtime CPU 커널(MLAS)은 INT8 QLinearConv/MatMulInteger를 정수 dot-product 명령이 있으면 그걸로 가속한다 — ARM은 SDOT/UDOT(asimddp), x86은 VPDPBUSD(AVX-512 VNNI 또는 AVX-VNNI). A76엔 asimddp가 있어 INT8 conv가 FP32보다 빨라진다. 반면 i9-10900K(Comet Lake)엔 VNNI가 없어(AVX2까지) INT8 경로가 dot-product 가속을 못 받고, 그 위에 QuantizeLinear/DequantizeLinear 노드의 추가 비용까지 얹혀 FP32 AVX2 경로보다 되레 느려진다. 같은 그래프·같은 런타임인데 ISA의 INT8 명령 유무 하나가 부호를 결정한다.
주의 이것은 CPU 폴백 경로의 이야기다. 4단계 SoC들의 NPU/DSP 가속기는 애초에 INT8 전용 MAC 어레이라 INT8이 항상 이긴다(그게 존재 이유). 부호 반전은 "가속기가 못 받아 CPU로 떨어진 부분"에서 벌어지는 일 — 즉 폴백이 많을수록 이 CPU ISA 특성이 최종 성능을 좌우한다. Pi 5처럼 dotprod 있는 Cortex-A76(예: 여러 최신 오토모티브 SoC의 A-코어)이라면 폴백조차 INT8이 유리하지만, 구형 A-코어(dotprod 없는 A53/A72)면 폴백 INT8이 되레 독이 된다.

§4 — 크로스플랫폼 예측 일치: FP32는 비트 동일, INT8은 아니다

해석 FP32는 IEEE-754 부동소수 연산이 두 ISA에서 사실상 동일 순서로 수행돼 1,000장 전부 같은 예측이 나온다 — "CPUEP는 크로스플랫폼 동일"이 FP32에선 문자 그대로 성립. 그러나 INT8 QDQ는 다르다: 정수 누산·재양자화 반올림이 SDOT(ARM)와 AVX2 정수 경로(x86)에서 미세하게 갈리고, 경계에 걸친 예측이 42장 뒤집힌다. 순 top-1 영향은 0.3%p로 작지만(둘 다 ≈0.75), "INT8은 FP32보다 수치가 ISA에 민감"이라는 건 실무에서 기억할 값이다 — 서로 다른 타겟에서 INT8 정확도를 비트 단위로 기대하면 안 된다. (ORT 버전도 다르지만 1.28.0/1.23.2, FP32 100% 일치가 버전이 주범이 아님을 시사 — 갈림은 ISA의 INT8 경로에서 온다.)

§5 — 부수 발견: golden 회귀 테스트는 설계상 TRT 전용

Pi/x86 CPU 4행을 5단계 벤치 매트릭스(bench/results/)에 봉인하려 하자, 커밋된 회귀 테스트가 깨졌다 — 그리고 그 자체가 하네스 통찰이었다.

pytest — CPU 행 주입 시 golden 붕괴, 격리 후 복원
# CPU 4행을 results/에 넣고 실행 — 임계값 2개는 통과, golden은 실패
$ pytest tests/test_regression.py -q
test_no_map_regression       PASSED   # baseline과 inner-merge라 새 행 제외 → 무영향
test_no_latency_regression   PASSED
test_matrix_matches_golden   FAILED   # Obtained (10,) vs Expected (6,) — shape 불일치
1 failed, 2 passed

# CPU 4행을 cpu_proxy/로 격리 → golden 다시 6행 → 복원
$ pytest tests/test_regression.py -q
... 3 passed in 0.20s
왜 섞으면 안 되나 golden 테스트는 dataframe_regression.check(..., atol=1e-3, rtol=1e-3)다. 결정론적 TRT 지연(0.8628ms를 매번 재현)에는 맞지만, 비결정 CPU wall-clock은 Pi 145ms를 ±0.145ms로 재현할 수 없다 — 열·스케줄러·부하로 수 ms씩 흔들린다. 즉 이 golden은 암묵적으로 TRT 결정론 백엔드 전용이다. CPU 프록시 행을 golden-glob되는 results/에 섞는 건 구조적으로 부적합 → 별도 cpu_proxy/results/로 분리해 커밋된 하네스는 6행·초록 유지. (임계값 층(A)은 baseline과 inner-merge라 애초에 새 SoC를 조용히 제외 — 이건 정책상 정상.)

§6 — 판정 · 산출물

확정 ✓ Pi CPU만으로 INT8 추론 — 가능·재현

GPU/NPU 없이 순수 CPUExecutionProvider로 FP32·INT8 완주. onnxruntime cp313 aarch64 휠이 PyPI에 있어 설치도 매끄러웠다. 원 질문("Pi CPU만 사용하는 방법으로 가능한가")에 대한 답은 가능이며, 스크립트·모델·서브셋으로 재현 가능하다.

발견 ✓ 양자화 이득의 부호는 CPU ISA가 결정

같은 INT8 QDQ·같은 ORT CPUEP인데 Pi 5(dotprod) INT8 ×1.83 빠름 vs x86(VNNI 없음) INT8 1.76× 느림. 가이드의 "양자화 이득은 하드웨어 의존" 논지를 CPU 축에서 직접 실증 — 폴백이 많은 SoC일수록 A-코어의 dotprod 유무가 최종 성능을 좌우한다.

정직화 ✓ Pi는 폴백 프록시일 뿐 NPU 아님

측정한 건 "모든 op가 CPU로 폴백된 바닥값". 자동차 NPU(QCS8550/RZ-V2H/TDA4VM) 가속 수치는 여전히 보드 대기(4단계 본 과제). CPU 행은 golden 결정론과 충돌해 cpu_proxy/로 격리, 커밋된 5단계 하네스는 6행·초록 유지.
