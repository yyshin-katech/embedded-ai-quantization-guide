DETR-on-Orin — 트랜스포머를 같은 보드에 올리면 무엇이 달라지는가

앞선 Orin 온디바이스 보고서는 ResNet50(깨끗한 CNN)으로 iGPU 정밀도 사다리와 DLA 오프로드를 실측했다. 이번엔 모델을 바꾼다 — facebook/detr-resnet-50, CNN 백본 + 트랜스포머 인코더/디코더. 같은 보드·같은 trtexec·같은 플래그라 지연은 1:1 비교 가능하다. 결과 세 줄: ① 무거운 트랜스포머는 INT8 연산 이득이 되살아난다(implicit ×2.74 — ResNet50은 INT8≈FP16였다) ② ORT 명시적 QDQ INT8이 파싱 자체를 못 한다(shiftIsAllZeros — 3단계 case C가 실 트랜스포머에서 재현) ③ DLA에 트랜스포머는 안 맞는다 — ResNet50의 깨끗한 2/2 오프로드가 DETR에선 GPU 폴백 404층·16조각 파편화로 무너져 iGPU FP16보다 30× 느리다.

사용자 요청 "새 모델 축" — 같은 Orin 보드에 ResNet50 대신 DETR를 올려, 정밀도 사다리·양자화 경로·DLA 적합성이 모델 종류에 따라 어떻게 갈리는지를 실측했다. 4가지 발견 모두 ResNet50 기준선과의 대비로 읽는다.

발견 1 · 무거운 트랜스포머는 INT8 이득이 되살아남 (모델 의존)DETR FP16 ×1.947, INT8(implicit) ×2.742(FP16→INT8 추가 ×1.408). ResNet50@224는 작은 Ampere iGPU에서 launch/메모리 바운드라 INT8≈FP16(0.984, 이득 거의 0)였는데, DETR@800×1066는 어텐션 대형 matmul로 compute 바운드라 INT8이 확실히 앞선다. "작은 iGPU는 INT8 무이득"은 iGPU가 아니라 가벼운 CNN의 성질이었다 — ResNet50 보고서 발견 4를 모델 축에서 반증.
발견 2 · accuracy-valid INT8 경로가 파싱 불가 (3단계 case C 확증)detr_int8.onnx(ORT QInt8: zp≠0 1085/1485 + INT32 bias DQ 149개)가 trtexec 직접 파서에서 노드 0에서 0.05초 만에 사망 — Assertion failed: shiftIsAllZeros(zeroPoint). 3단계에서 ResNet50·합성으로 세운 case C(zp≠0)가 실 트랜스포머 ORT export에서 그대로 재현. 결과: Jetson trtexec에선 정확도 유효 INT8을 QDQ 수술(3단계 nodes_to_exclude/ORT-EP) 없이 못 얻는다. implicit --int8은 빌드되지만 자동 레인지 → 지연만 유효.
발견 3 · DLA에 트랜스포머는 안 맞음 (파편화, 헤드라인)ResNet50에 깨끗한 2/2 오프로드(GPU폴백 2층)를 준 그 recipe가 DETR에선 DLA 326층 / GPU폴백 404층 / 16조각. 폴백은 트랜스포머 비-DLA 연산(250 SHUFFLE·34 MATMUL·30 LayerNorm·12 SELECT) — DLA 적격 연산을 16개 섬으로 쪼개 매 경계마다 DLA↔GPU 복사. 결과 398.6ms = iGPU FP16(13.28ms)보다 30배 느림. DLA는 CNN 가속기 — 트랜스포머는 iGPU에.
발견 4 · DLA는 여전히 INT8 전용기 (규칙 불변)DLA INT8(78.48ms)은 DLA FP16(398.6ms)보다 5.08× 빠르다 — DLA에 남은 섬들에서 ResNet50의 "NVDLA=INT8 전용기" 규칙이 유지됨. 하지만 그래도 iGPU INT8(9.43ms)보다 8.3× 느리다. DLA 위에서 INT8을 켜도 파편화 페널티는 못 이긴다.
CAVEAT 모든 지연 = trtexec GPU Compute median(디바이스 event-timed, H2D/D2H 제외) · batch1 · MAXN, ResNet50 보고서와 동일 플래그(--warmUp=2000 --duration=10 --iterations=200 --avgRuns=100)라 그 보고서와만 1:1, 타 단계(polygraphy·wall-clock)와는 상대만. iGPU/DLA INT8은 implicit --int8(자동 레인지) → 지연·엔진크기 유효, 정확도 미주장. 정확도는 stage2 RTX 3080에서 인용: FP32 mAP 0.4207 → INT8(ORT QDQ) 0.2402(−42.9%), 작은 객체 mAP_s −77%.

§4 — explicit QDQ INT8 파싱 실패 (3단계 case C 확증)

정확도 유효 경로는 명시적 QDQ(detr_int8.onnx, ORT quantize_static). 이걸 trtexec 직접 파서에 넣으면 — 노드 0에서 즉사.

범인ORT quantize_static(QuantType.QInt8)는 활성화 zero-point를 0이 아니게 만든다(int8 범위 안의 비대칭). 인트로스펙션: detr_int8.onnx의 Q/DQ 1485개 중 1085개가 zp≠0 + 149개 Conv/Gemm 전부에 INT32 bias DQ. 첫 DQ 노드(/model/Tile — DETR 위치 임베딩 타일)가 zp≠0이라 바로 shiftIsAllZeros 위반.
3단계와의 연결3단계(RTX·polygraphy)는 case B(INT32 bias DQ)와 case C(zp≠0, shiftIsAllZeros)가 직접 파서의 독립 하드 블로커임을 ResNet50·합성 절제로 확립했다(3단계 보고서). 여기서 같은 case C가 실 트랜스포머의 ORT export에서 노드 0부터 그대로 재현 — 통념이 아니라 재현.
왜 ResNet50은 파싱됐나같은 보드에서 resnet50_int8_qdq.onnx는 --int8로 빌드됐다(1.013ms). 그 자산은 대칭(zp=0)으로 export됐기 때문. DETR 자산은 stage2에서 정확도용으로 ORT 기본(QInt8 비대칭 활성화)으로 만든 것이라 zp≠0 → 파서가 거부. 같은 도구·다른 export 정책이 결과를 가른다.
해결 경로정확도 유효 INT8을 Jetson trtexec로 얻으려면 (a) 대칭 재양자화(ORT extra_options로 활성화 대칭 강제 — 3단계 §2.2.1) 또는 (b) ORT-EP / nodes_to_exclude 경로(파서 전 QDQ 수술로 bias DQ 흡수). 이번 실측 목적은 지연 사다리 + DLA 적합성이므로, INT8 지연은 implicit(§3, 자동 레인지)로, 정확도는 stage2 인용으로 분리했다.

DLA 오프로드 vs GPU 폴백 — 레이어 배치 (막대폭 = 레이어수 × 0.8px)

■ DLA 오프로드   ■ GPU 폴백. ResNet50은 거의 전부 DLA(폴백 2층), DETR은 절반 이상이 GPU로 튕겨나가며 16조각으로 파편화.

GPU 폴백 404층의 정체250 SHUFFLE(어텐션 헤드 reshape/transpose) · 66 CONSTANT · 34 MATRIX_MULTIPLY(Q·Kᵀ, score·V — NVDLA v2엔 동적 matmul 없음) · 30 NORMALIZATION(LayerNorm — NVDLA v2 미지원) · 12 UNARY · 12 SELECT(마스크 Where). 전부 트랜스포머 고유 연산.
16조각의 정체DLA 적격 연산이 16개 섬으로 쪼개짐 — 1개 = ResNet 백본(conv1…input_projection), 4개 = encoder self-attn Mul 블록, 11개 = FFN Gemm 블록. 섬 사이마다 GPU 폴백층이 끼어 DLA↔GPU 텐서 복사 + 동기화. 16 왕복 = 398.6ms.
INT8도 못 구함DLA INT8(78.48ms)은 DLA FP16(398.6ms)보다 5.08× 빠르지만(DLA 섬들의 INT8 처리량), 여전히 iGPU INT8(9.43ms)보다 8.3× 느림. 파편화 페널티 > 정밀도 이득.

DLA는 트랜스포머에서 지연 재앙 — iGPU 대비 (막대폭 = 지연 ms × 1.4px)

기준 = iGPU FP16 13.28ms. DLA는 파편화로 배보다 배꼽이 크다.

설계 규칙 (일반화) DLA는 DLA 서브그래프의 GPU 폴백층이 ~0일 때만 이득이다. 이는 동시부하 실측에서 이미 ResNet50의 폴백 2층조차 동시부하 때 직렬화 병목이었던 것의 극단 사례 — DETR의 404 폴백 + 16 파편은 단독 실행만으로도 재앙. DLA는 CNN 가속기다. 트랜스포머 detection 헤드는 iGPU에 두고, DLA엔 순수 CNN(백본·분류기)만 올려라.

§6 — 판정·산출물

DONE iGPU 정밀도 사다리 (새 모델 축)

DETR FP32 25.85 → FP16 13.28(×1.95) → INT8 9.43ms(×2.74, implicit). ResNet50보다 13× 무겁지만 INT8 이득은 오히려 큼(compute 바운드). "작은 iGPU는 INT8 무이득"이 모델 의존임을 반증.

BLOCKED→확증 explicit QDQ INT8

ORT QInt8 QDQ가 shiftIsAllZeros로 노드 0에서 파싱 실패. 3단계 case C(zp≠0)가 실 트랜스포머에서 재현. 정확도 유효 INT8은 대칭 재양자화/ORT-EP 필요 — 지연은 implicit로, 정확도는 stage2 인용으로 분리.

헤드라인 DLA에 트랜스포머는 부적합

같은 recipe가 ResNet50 2/2 → DETR 404 GPU폴백·16조각. DLA FP16 398.6ms = iGPU FP16의 30×. DLA INT8(78.48)도 iGPU INT8의 8.3× 느림. DLA=CNN 가속기, 트랜스포머는 iGPU에.

CITED 정확도 (미측정)
