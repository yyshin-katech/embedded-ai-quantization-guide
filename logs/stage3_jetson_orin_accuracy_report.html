온디바이스 정확도 — Orin 실리콘 위에서 INT8은 살아남는가

앞선 Orin 온디바이스 보고서(솔로 스윕, 커밋 00fd97d)는 지연·전력만 실측하고 정확도는 명시적으로 측정하지 않았다(summary.json: "DLA INT8 = implicit … accuracy not claimed"). 이 빈칸을 닫는다 — 저장된 .plan 엔진을, 4단계 Jetson A78AE CPU-프록시가 쓴 바로 그 1000장 번들(커밋 49e30ff)에 돌려 이미지별 예측을 1:1 대조한다. 과학적 훅: 4단계는 INT8 예측이 정수커널 경로 의존임을 CPU들 사이에서 밝혔다(Jetson↔Pi5 100% 같은 MLAS SDOT; Jetson↔x86 958/1000 다른 커널; FP32는 항상 100%). 여기선 훨씬 큰 경계를 넘는다 — CPU 정수커널(MLAS) vs GPU/DLA 정수커널(TensorRT), 같은 보드·같은 QDQ scale(둘 다 resnet50_int8_qdq.onnx)에서.

사용자 요청 "온디바이스 정확도 측정" — 같은 Orin 보드에서 가속기(TRT) INT8 정확도가 RTX/CPU-프록시 수준으로 유지되는지, 그리고 TRT INT8 예측이 같은 실리콘의 MLAS INT8 예측과 일치하는지를 실측했다. 5가지 발견 모두 같은 1000장 번들 위 상대 관계로 읽는다.

발견 1 · INT8 경로 의존이 CPU↔가속기 경계를 넘는다 (헤드라인)TRT INT8(GPU 정수커널)과 MLAS INT8(CPU SDOT 커널)은 같은 QDQ scale을 같은 Orin 실리콘에서 돌리는데 39/1000장(96.1% 일치)에서 갈린다. 이 96.1%는 stage4의 Jetson↔x86 CPU 교차(958/1000 = 95.8%)와 같은 대역이고, Jetson↔Pi5의 100%(같은 MLAS SDOT)가 아니다. 규칙이 깔끔히 일반화된다 — 정수커널이 다르면 ~96%, 경계가 CPU↔CPU든 CPU↔가속기든 무관; 같으면 100%. INT8 top-1은 데이터패스 간 비트 재현이 안 된다(FP32만 된다 — 여기서 1000/1000).
발견 2 · accuracy-valid INT8이 온디바이스에서 유지 (게다가 CPU 커널을 이김)온디바이스 iGPU INT8(explicit QDQ, 3단계 실 scale) top-1 = 0.7620 = FP32, 즉 1000장 입도에서 무손실 — 그리고 CPU MLAS INT8(0.7500)보다 높다. 39장 불일치에서 TRT 정답 15 · MLAS 정답 3 · 둘 다 오답 21(net +12 = 0.762−0.750). 같은 scale인데 반올림·누산이 달라, 여기선 TensorRT 정수 데이터패스가 더 충실하다.
발견 3 · "top-1 불변" ≠ "예측 불변"iGPU INT8은 iGPU FP32와 top-1이 정확히 같다(0.762)지만 예측은 57/1000장 뒤집힌다(라벨 대비 net-neutral). top-1만 보면 실제 이미지별 churn이 가려진다 — 정직한 산출물은 pred_cls 배열이다. 부수 효과: 943≠1000이라 INT8 엔진이 FP32로 무음 폴백한 게 아님을 자체 증명(게다가 3단계에서 INT8 지연 1.01ms ≠ FP32 1.94ms).
발견 4 · FP16은 사실상 무손실 · DLA fp16 데이터패스는 2장 차이iGPU FP16 = FP32 대비 999/1000(1장 플립). DLA FP16 = 0.7610(iGPU FP16 대비 998/1000) — NVDLA v2 fp16 데이터패스가 iGPU와 미세하게 다르나(별개 가속기니 당연) 정확도는 등가.
발견 5 · implicit DLA INT8은 0.017로 붕괴 (캐비앗 정량화)rn50_dla_int8.plan은 trtexec --int8 + 캘리브 데이터 없음으로 빌드 → 자동 dynamic-range → top-1 0.0170(near-random). 같은 하네스가 DLA FP16 = 0.761을 주므로 하네스 버그가 아니다 — 이것이 솔로 스윕이 DLA/implicit INT8을 지연 유효·정확도 미주장으로 라벨한 이유다. accuracy-valid INT8 엔진은 explicit-QDQ iGPU 쪽(발견 2)이다.
CAVEAT 절대 top-1은 1000장 서브셋(1단계 함정 0: 서브셋 top-1은 전체 50k 대비 부풀려짐)이라 3단계 5000장 RTX 수치와 비교 불가 — 같은 번들 위 상대 관계(일치율·INT8 vs FP32·TRT vs MLAS)만 결과다. dla_int8(0.017)은 implicit 자동 레인지라 캐비앗 정량화용일 뿐 DLA INT8 정확도가 아니다. Jetson은 NVIDIA edge이지 세 자동차 벤더(TI/Qualcomm/Renesas) 아님.

§4 — 경로 의존: TRT INT8 vs MLAS INT8 (헤드라인)

이미지별 pred_cls를 1:1 대조한 일치 수. FP32는 데이터패스가 달라도 비트 동일(1000)이지만, INT8은 정수커널이 다르면 갈린다.

iGPU INT8 (TRT) vs CPU INT8 (MLAS SDOT)96139헤드라인 — 같은 QDQ scale인데 경로가 다름

예측 플립 수 (1000 − 일치) — 낮을수록 데이터패스 간 재현성 높음

막대폭 = 플립 × 9px (0 플립은 시각화용 최소 sliver). FP32(0)와 INT8(39·57)의 대비가 "경로 의존은 INT8만"을 보여준다.

STAGE4 연결 이 96.1%(39 플립)를 4단계 CPU 교차와 나란히 놓으면 규칙이 보인다:
Jetson iGPU-TRT ↔ Jetson CPU-MLAS (본 실측)961/1000 — 다른 정수커널(TRT vs MLAS) · CPU↔가속기 경계
Jetson CPU ↔ x86 CPU (stage4)958/1000 — 다른 정수커널(MLAS SDOT vs no-VNNI) · CPU↔CPU
Jetson CPU ↔ Pi5 CPU (stage4)1000/1000 — 같은 정수커널(둘 다 MLAS SDOT)
임의 FP32 교차쌍 (본 실측 + stage4)1000/1000 — FP32는 경로 무관 결정론적
결론: INT8 예측 재현성은 실리콘 종류(CPU/GPU/DLA)가 아니라 정수커널 경로가 가른다 — 같으면 100%, 다르면 ~96%. accuracy-valid INT8을 옮길 때 top-1은 보존돼도(발견 2) 이미지별 예측은 비트 재현되지 않는다.
불일치 분해 (39장) TRT INT8과 MLAS INT8이 갈리는 39장에서 TRT 정답 15 · MLAS 정답 3 · 둘 다 오답 21. net +12(=0.762−0.750). 두 커널은 같은 QDQ scale을 쓰지만 정수 누산·재양자화 반올림이 다르고, 이 모델·이 번들에선 TensorRT 데이터패스가 더 충실했다. (일반화 금지 — 모델·번들 의존.)

§5 — 판정·산출물

YES accuracy-valid INT8은 Orin 실리콘에서 유지된다

iGPU INT8(explicit QDQ, 실 scale) top-1 = 0.7620 = FP32(1000장 무손실), CPU MLAS INT8(0.750)보다도 높다. 3·4단계에서 "가속기가 이겨야 할 CPU 바닥값"을 세웠다면, 이 실측은 그 위에서 가속기 INT8이 정확도를 잃지 않고 이긴다는 걸 온디바이스로 확인한다.

경로 의존 INT8 예측은 데이터패스 간 비트 재현 안 됨

TRT INT8 vs MLAS INT8 = 961/1000. stage4의 CPU↔CPU 경로 의존(958 vs 1000)이 CPU↔가속기 경계에서도 같은 대역으로 재현된다. 규칙: 정수커널 같으면 100%, 다르면 ~96% — 실리콘 종류 무관. FP32만 경로 무관(1000/1000).

CAVEAT implicit INT8 정확도는 주장하지 않는다

DLA implicit INT8 = 0.017(자동 레인지 붕괴). 같은 하네스가 DLA FP16 = 0.761을 주므로 하네스는 정상 — 이 값은 "캘리브 없는 자동 레인지"의 정량화일 뿐, accuracy-valid INT8은 explicit-QDQ iGPU 엔진이다.
