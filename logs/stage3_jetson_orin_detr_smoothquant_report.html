DETR 온디바이스 SmoothQuant — activation 입도 레버가 INT8 폭락을 되찾는가

앞선 DETR 정확도 보고서(커밋 58ba518)는 accuracy-valid explicit-sym INT8이 stage2 폭락을 재현한다고 판정했다(FP32 0.4237 → INT8 0.2383, −43.8%) — 그리고 레버는 case-C 픽스나 대칭 여부가 아니라 activation 양자화 입도(SmoothQuant, stage2 §4.4)라고 지목했다. stage2 §4.4는 그 레버로 폭락의 59.9%를 되찾았지만 — torch fake-quant 경로(Design X)에서만이고 ONNX→TRT 온디바이스에선 한 번도 측정된 적이 없다. 이 후속은 그 빈칸을 닫는다: ONNX-레벨 SmoothQuant를 95개 Gemm에 직접 적용해 accuracy-valid 대칭 INT8 엔진을 다시 빌드하고, 같은 보드·같은 1000장에서 폭락이 되돌아오는지 실측한다.

과제(메모리 verbatim): "SmoothQuant(activation 입도)로 DETR INT8 폭락이 온디바이스에서 회복되는가 — stage2 §4.4의 59.9%가 ONNX→TRT 경로로 전이되는가." 세 발견 모두 같은 보드·같은 1000장·같은 800×1066 전처리·같은 대칭 QDQ 레시피 위 상대 관계로 읽는다 — 유일한 변수는 SmoothQuant activation migration(Mul 95개).

발견 1 · 온디바이스 SmoothQuant는 폭락의 ~9%만 회복한다 — stage2의 1/6 (헤드라인)ONNX-레벨 SmoothQuant(α=1.0, 95 Gemm, activation absmax 최대 46.699×/중앙 7.485× 압축)를 대칭 INT8 엔진에 얹으니 mAP 0.2383 → 0.2553 — 0.1854 폭락 gap 중 9.2%(+0.0170)뿐. stage2 §4.4는 같은 레버로 59.9%를 되찾았다(torch fake-quant). 같은 레버가 경로에 따라 한 자릿수 배 다르게 작동한다.
발견 2 · 근본 원인 = op 커버리지 (SmoothQuant가 틀린 게 아니다)온디바이스에서 빌드 가능한 유일한 INT8 엔진은 attention MatMul·LayerNorm·Softmax를 FP16으로 남긴다(58ba518의 case-C 파서 + quantized-constant 빌더 벽이 op_types_to_quantize=[Conv,Gemm]를 강제). 그래서 INT8은 Gemm 전용이고, Gemm 입력을 매끈하게 만드는 것은 이 경로의 지배적 잔차 오차원이 아니다. stage2 torch 경로는 attention Q/K/V/out을 포함한 모든 linear가 per-tensor INT8이라 SmoothQuant가 크게 먹혔다.
발견 3 · 단 SmoothQuant는 방향이 옳다 — α 순서 보존 + mAP_s 부분 회복 + 거의 지연 중립α=1.0(9.2%) > α=0.5(8.7%)로 stage2의 DETR-best α=1.0 순서를 보존. 폭락이 집중된 작은 객체 mAP_s도 0.0336 → 0.0449(gap의 6.1% 부분 회복). 대가는 Mul 95개뿐이라 거의 지연 중립(+0.3413 ms·엔진 +0.18 MiB). 엔진이 진짜 INT8임도 확인(FP32 대비 logits_corr 0.9826·sym과 logits_absmax 16.43로 실제 다름 — 무음 FP32/sym 복제 아님).
CAVEAT 절대 mAP는 stage2와 비교 불가 — fixed 800×1066 vs stage2 dynamic shape, TRT vs ORT torch fake-quant, 1000 vs 5000장. 같은 번들 안의 상대 회복(recovery-of-gap)만 결과다. 1000장 서브셋(1단계 함정 0: 서브셋 mAP도 부풀려짐). SmoothQuant는 구성상 FP32-정확(s가 상쇄, gate max_abs 1.7e-4 · CPU EP) — 이득은 오직 outlier 이주 후 더 조밀해진 per-tensor activation 양자화에서 온다. Jetson은 NVIDIA edge이지 세 자동차 벤더(TI/Qualcomm/Renesas) 아님.

§3 — ONNX-레벨 SmoothQuant (수동)

stage2 §4.4 SmoothQuant는 torch fake-quant 경로(Design X)에서만 살았고 ONNX를 낳지 않아 온디바이스로 올릴 수 없었다. modelopt.onnx도 임포트 불가(onnxslim 없음). 그래서 SmoothQuant를 ONNX 그래프에 직접 손으로 심었다.

SmoothQuant 수학 — DETR의 95개 Gemm 전부 transB=0 (Y=A·B, weight [K,N])
# 수축 축 K = A.shape[-1] = B.shape[0] (weight 행). 채널별 이주 스케일:
s_k = a_k^α / w_k^(1-α)   # a_k = 캘리브 100장의 per-channel(K) activation absmax, w_k = per-row(axis0) weight absmax
A'[:,k] = A[:,k] / s_k    # activation에 Mul(A, 1/s) 삽입 (마지막 축 broadcast)
B'[k,:] = B[k,:] · s_k    # weight 행 k를 s_k배 (W * s[:,None])
A'·B' = A·B   (임의의 s>0에 대해 수학적으로 정확 — outlier를 activation→weight로 이주만)
# 이득은 오직: activation의 채널별 outlier가 weight로 옮겨가 per-tensor activation 레인지가 조밀해짐
FP32 정확도 게이트 — CUDA EP가 아니라 CPU EP에서 (교훈)
# CUDA EP로 게이트 → max_abs=0.65 오검출. 원인: Ampere TF32 matmul(10-bit 가수)이
#   SmoothQuant의 피연산자 재스케일에 민감 → ~1e-2 허위 diff (배선 버그 아님, 정밀도 artifact)
providers=["CPUExecutionProvider"]  → max_abs = 1.748e-4 (α=1.0) / 1.450e-4 (α=0.5)  PASS (<1e-2)
# 순수 numpy SmoothQuant 수학 자체는 1.4e-14로 정확 · 95개 Gemm 전부 distinct weight (공유 없음)
대칭 재양자화 — 58ba518과 동일 레시피 (case-C/B/attention 3벽 우회)
quantize_static(SMOOTH, DST, quant_format=QDQ, activation_type=QInt8, weight_type=QInt8,
  per_channel=True, op_types_to_quantize=["Conv","Gemm"],           # attention MatMul/LayerNorm/Softmax는 FP16 (빌더 벽)
  nodes_to_exclude=["/model/backbone/model/conv1/Conv"],           # case D (stem conv)
  extra_options={ActivationSymmetric:True, WeightSymmetric:True,    # zp=0 → case C (shiftIsAllZeros) 해소
                 QuantizeBias:False})                              # INT32 bias DQ 제거 → case B 해소
VERIFY  zp_total=732  zp_nonzero=0  int32_bias_DQ=0  SQMul_kept=95   # Mul은 op_types 밖이라 FP로 남음
# SmoothQuant Mul을 제외한 QDQ 그래프는 sym과 byte-동일(43,612,561 B) — 유일 델타 = Mul 95개
SmoothQuant activation 압축 (absmax 배율)최대최대 위치중앙값≥2× Gemm정확도 게이트
α=1.0 (a10)46.699×Gemm_47.485×94/951.748e-4
α=0.5 (a05)19.265×Gemm_45.51×95/951.450e-4
핵심 SmoothQuant를 ONNX 그래프에 직접 심어 stage2가 torch에만 갖고 있던 레버를 처음으로 온디바이스에 올렸다. α=1.0은 activation absmax를 최대 46.7×·중앙 7.49× 감쇠 — outlier가 실제로 크게 이주했다. 남은 질문은 "이 조밀해진 activation 양자화가 폭락을 얼마나 되찾는가"이고, §4가 답한다.

gap 회복률 — SmoothQuant가 sym→FP32 폭락(0.1854)을 얼마나 메우는가 (길수록 회복)

막대폭 = 회복률(%) × 5.5px. 황=온디바이스(ONNX→TRT, Gemm 전용 INT8), 회색=온디바이스 mAP_s(작은 객체) 회복, 빨강=stage2 §4.4(torch fake-quant, 모든 linear INT8). 같은 SmoothQuant 레버인데 경로/op-커버리지에 따라 약 6.5배 차이.

헤드라인 ONNX-레벨 SmoothQuant를 온디바이스에 처음 올렸지만, 폭락의 9.2%(α=1.0)만 되찾는다 — stage2 §4.4의 59.9%보다 약 6.5배 작다. 같은 레버, 다른 결과: 근본 원인은 SmoothQuant가 틀려서가 아니라 op 커버리지다. 온디바이스에서 빌드 가능한 유일한 INT8 엔진은 attention MatMul·LayerNorm·Softmax를 FP16으로 남기므로(58ba518의 파서·빌더 벽) INT8은 Gemm 전용이고, Gemm 입력 smoothing은 이 경로의 지배적 잔차 오차원이 아니다. stage2 torch 경로는 attention Q/K/V/out을 포함한 모든 linear가 INT8이라 SmoothQuant가 크게 먹혔다. 이는 stage2 §4.4의 59.9%를 부정하는 게 아니라 경로·op-커버리지 의존임을 정밀화한다(교차확증 반전).
방향은 옳다 SmoothQuant가 무효인 건 아니다: (1) α=1.0(9.2%) > α=0.5(8.7%)로 stage2의 DETR-best α=1.0 순서를 보존, (2) 폭락이 집중된 작은 객체 mAP_s가 0.0336 → 0.0449(gap의 6.1%)로 부분 회복 — SmoothQuant가 올바른 방향으로 민다는 정성적 증거. 단 그 크기가 이 경로에선 modest할 뿐.
부수 · 진짜 INT8인가 FP32 대비 raw 발산: sq_a10 logits_corr 0.98258·boxes_corr 0.94758(sym 0.98236/0.94532과 유사=진짜 INT8). sym 대비 발산: sq_a10 logits_absmax 16.4336 — SmoothQuant 엔진은 sym과 실제로 다르다(무음 sym 복제 아님). 즉 회복이 작은 건 엔진이 안 바뀌어서가 아니라 바뀐 방향의 레버가 이 경로에서 modest하기 때문.

§5 — 지연·엔진 (거의 중립)

지연 — batch1 GPU Compute median (짧을수록 빠름)

막대폭 = 지연(ms) × 18.57px. SmoothQuant(초록)는 sym(파랑)에 Mul 95개만 더해 거의 겹친다(+0.34/+0.41 ms) — activation 입도 레버는 사실상 공짜지만, 그 대가로 얻는 회복도 이 경로에선 작다(§4).

읽는 법 SmoothQuant 막대는 sym 위에 거의 포개진다 — activation migration은 지연·크기 면에서 사실상 무료다. 이것이 SmoothQuant의 매력(공짜 레버)이지만, DETR 온디바이스에선 그 공짜 레버가 되찾는 정확도도 작다(9.2%). 레버가 싸다 ≠ 레버가 강력하다 — 강력함은 op 커버리지(무엇이 INT8인가)에 달렸다.

§6 — 판정·산출물

NO stage2 §4.4의 59.9% 회복은 온디바이스로 전이되지 않는다 — 폭락의 ~9%만 회복

ONNX-레벨 SmoothQuant(α=1.0)는 mAP 0.2383 → 0.2553, 0.1854 gap의 9.2%뿐. stage2 §4.4의 59.9%보다 약 6.5배 작다. 근본 원인은 SmoothQuant가 아니라 op 커버리지 — 온디바이스 INT8은 Gemm 전용(attention/LayerNorm/Softmax는 FP16, 58ba518 파서·빌더 벽), stage2 torch는 모든 linear가 INT8. stage2 §4.4의 판정을 부정하는 게 아니라 "경로·op-커버리지 의존"으로 정밀화한다.

MIXED 단 SmoothQuant는 방향이 옳다 — α 순서 보존 + mAP_s 부분 회복 + 거의 지연 중립

α=1.0(9.2%) > α=0.5(8.7%)로 stage2의 DETR-best α=1.0 순서를 보존. 폭락이 집중된 작은 객체 mAP_s가 0.0336 → 0.0449(6.1%)로 부분 회복. 대가는 Mul 95개뿐 = +0.3413 ms·+0.18 MiB(거의 중립). 레버는 싸지만 이 경로에선 modest.
