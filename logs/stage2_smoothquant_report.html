§4.4 SmoothQuant — DETR INT8 회복 실측 검증 보고서

DETR 실측(§4.5)이 지목한 "진짜 레버 = activation 양자화 입도"를 SmoothQuant로 직접 시험했다. facebook/detr-resnet-50을 torch fake-quant 경로에서 자기일관 3원(FP32 / per-tensor INT8 max / 동일 입도 + SmoothQuant)으로 COCO val2017 전량 5,000장 mAP를 재고, modelopt 프리셋 API·스무딩 전후 채널 absmax·α 스윕까지 실측했다. 초안(04_transformer_quantization.md §4.4)의 "⚠️ API 확인 필요"와 "다음 검증 과제로 남긴다"를 실측으로 종결한다. 핵심 발견: op-선택으로는 못 되찾던 폭락을 SmoothQuant는 59.9% 되찾는다 — 도구 기본 α는 논문 권장(0.5)이 아니라 1.0.

DETR §4.5의 미결 처방(SmoothQuant)을 실측해 방향을 확증했다. 상세는 각 절.

① API 확인 필요 해소modelopt 0.45.0 INT8_SMOOTHQUANT_CFG = {quant_cfg, algorithm:"smoothquant"}. INT8_DEFAULT_CFG와 algorithm만 다르다(weight per-ch axis 0·act per-tensor axis null 동일) → SmoothQuant 효과를 단독 격리하는 깨끗한 A/B. (3절)
② 초안 α 오류 정정초안 "modelopt 기본 α=0.5" → 실측 프리셋 기본은 α=1.0(문자열 프리셋→빈 kwargs→smoothquant(alpha=1.0)). 논문 권장 0.5는 {"method":"smoothquant","alpha":0.5} dict-override로 지정(문법 유효 실증). (3·5절)
③ 회복은 실재op-선택 mixed가 +0.36 mAP뿐이던(§4.5) 폭락을, SmoothQuant는 +0.0544 mAP(gap의 59.9%) 되찾는다 → "진짜 레버 = activation 입도"(§4.5 판정 4) 확증. (4절)
④ 메커니즘 실측대상 Linear 입력 채널 absmax spike가 3.69× → 1.96×로 눌린다(스무딩이 실제로 outlier를 weight로 이전). (6절)
캐비앗(먼저) 본 보고서 절대 mAP는 torch fake-quant 경로(modelopt)이고 커밋된 §4.5의 ORT QDQ 절대값(0.4207/0.2402)과 양자화 커널이 다르다. 따라서 절대값 1:1 비교가 아니라 같은 경로 안의 상대 관계(SmoothQuant 회복분·α 방향·absmax 감쇠)가 유효 결론이다 — 가이드의 상시 캐비앗과 동일.

§3 — modelopt API 실측 (초안 "확인 필요" 종결)

초안 §4.4는 config["algorithm"]={"method":"smoothquant","alpha":0.5} override와 "alpha 기본 0.5"를 "⚠️ 확인 필요"로 달아뒀다. 실제 0.45.0 API를 sq_01로 기록했다.

mtq.quantize 시그니처(model, config: dict, forward_loop=None) -> Module
INT8_SMOOTHQUANT_CFGtop keys ["quant_cfg","algorithm"] · algorithm = 문자열 "smoothquant" · weight_quantizer {num_bits 8, axis 0(per-channel)} · input_quantizer {num_bits 8, axis null(per-tensor)}
INT8_DEFAULT_CFGalgorithm = "max" · axes는 위와 동일 → 두 프리셋은 algorithm만 다르다(깨끗한 A/B의 근거)
dict-override 유효성mtq.quantize는 algorithm에 문자열 또는 {"method":...} dict 모두 수용(model_quant.py:511, mode.py:377-380). 초안의 dict override 문법은 유효 — sq_04가 α=0.5/1.0로 실제 mAP를 바꿔 실증(override_worked=true).
🔴 초안 α 정정문자열 프리셋은 dispatch에서 빈 kwargs로 풀려 smoothquant(model, fwd)의 기본 alpha=1.0(model_calib.py:954)을 쓴다. 초안 "기본 0.5"는 논문 권장값(§참고문헌)을 도구 기본값으로 오귀속한 것 — 실제 도구 기본은 1.0(모든 outlier를 weight로 이전).
A/B 설계 두 프리셋이 algorithm만 다르므로, 같은 캘리브·같은 비트폭·같은 축에서 max → smoothquant로 바꾼 mAP 차이가 순수 SmoothQuant 효과다. 다른 변수가 섞이지 않는다.

§4.5에서 op-선택 mixed(attn 36개 FP)는 +0.36 mAP뿐이었다. 같은 폭락을 SmoothQuant는 +0.0544 mAP(gap의 59.9%) 되찾는다. "op를 몇 개 빼기"가 아니라 "activation outlier 자체를 구조적으로 없애기"가 옳은 방향임을 실측이 지지한다(§4.5 판정 4·5.2 핵심 해석).

주의 이 삼원은 같은 torch fake-quant 경로 안의 대조다. 커밋된 §4.5 ORT 절대값과 직접 비교하지 말 것(캐비앗 §1). 회복분·회복%가 결론.

§5 — α(migration strength) 스윕

도구 기본 α=1.0과 논문 권장 α=0.5의 회복 차이를, 같은 서브셋(앞 500장)에서 격리(sq_04). dict-override가 실제로 α를 바꾸는지도 실증.

α 판정 이 DETR/COCO 서브셋에선 α=1.0(modelopt 프리셋 기본)이 α=0.5(논문 권장)보다 더 회복한다(66.6% vs 49.8%). LayerNorm outlier가 극심한 검출 모델에선 activation을 전량 weight로 이전(α=1.0)하는 게 유리 — LLM용으로 튜닝된 0.5가 항상 최적은 아니다. dict-override가 두 α에서 서로 다른 mAP를 내므로(override_worked=true) 초안의 alpha 지정 문법 자체는 유효하다 — 다만 어느 α가 최적인지는 모델·데이터 의존이며, "그냥 프리셋"은 α=1.0을 뜻한다는 점을 알고 써야 한다.

§6 — 스무딩 전/후 채널 absmax (메커니즘)

SmoothQuant가 실제로 activation spike를 눌러 weight로 넘기는지, 대상 Linear 입력의 채널별 absmax를 스무딩 전(raw)/후(× pre_quant_scale)로 비교(sq_03). 순환 측정을 피하려 캘리브 셋(64)과 측정 셋(24)을 분리.

대상 Linearmodel.encoder.layers.0.self_attn.k_proj (in_features 256)
스무딩 전 (raw)max 38.879 · median 10.525 · ratio 3.69×
스무딩 후 (× pqs)max 1.653 · median 0.844 · ratio 1.96×
pre_quant_scale 범위0.0213 ~ 0.1628 (채널별 1/s, per-channel)
메커니즘 확인 채널 간 spike(max/median)가 3.69× → 1.96×로 절반 가까이 줄었다. per-tensor scale을 끌고 가던 outlier 채널이 weight 쪽으로 이전돼(§2.2 등가변환 Y=(X/s)(sW)), activation이 per-tensor INT8에 더 잘 담긴다. 이것이 4절 회복의 물리적 근거다. (초안 예시 31.7×→2.96×는 삽화값 — 실측 k_proj는 3.69×→1.96×.)
