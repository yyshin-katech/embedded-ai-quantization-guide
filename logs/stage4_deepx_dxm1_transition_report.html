실행 보고서 · 4단계 · DX-M1 레짐 전이 곡선 (Raspberry Pi 5 온디바이스)

DEEPX DX-M1 — compute-bound ↔ D2H-bound 전이 곡선

크로스오버 축은 두 레짐의 존재를 증명했다 — 출력 4KB의 resnet50은 compute-bound(3코어 2.19× 스케일), 출력 2.82MB의 yolo26n은 D2H-bound(1.00× 평평). 하지만 그건 두 끝점이었고 그 사이 전이는 미측정이었다(캐비앗 #3: "2 regime의 존재를 증명, 전이 곡선 아님"). 이 축은 그 곡선을 그린다: 고정된 무거운 conv 트렁크(연산 2.70ms 고정, resnet50급)에 4채널 병목 + 1×1 확장 헤드를 붙여 연산은 그대로 두고 출력(D2H) 크기만 1020× 스윕한다(합성 모델 12점, 랜덤 가중치 → 지연·레짐만 주장). 결과: 3코어 스케일링이 2.98× → 1.00×로 매끄럽게 전이하고, 코어 잡 분포가 33/33/33 → 98/2/0으로 이동하며, 전이는 knife-edge가 아니라 ~3배(=코어 수) 폭의 밴드임이 드러난다.

헤드라인 크로스오버 축이 증명한 두 레짐은 연속 스펙트럼의 양 끝이었다. 연산을 2.70ms로 고정하고 출력만 키우면, 코어 스케일링이 2.98×(순수 compute-bound) → 1.00×(순수 D2H-bound)로 단조 전이한다. 더 나아가 전이는 하나의 임계점이 아니라 두 개다 — (1) 출력 ~319KB에서 3코어 스케일이 깨지기 시작(공유 링크가 한 코어치 D2H의 3배를 못 감당)하고, (2) 출력 ~1.05MB에서 단일 추론마저 D2H-bound가 된다(D2H가 고정 연산 2.70ms를 추월). 두 임계점 사이 ~3.36× 폭의 밴드가 곧 코어 수 — N개 코어가 D2H 링크 하나를 공유하므로 멀티코어 처리량은 단일추론 병목의 1/N에서 이미 포화한다.

§2 — 방법 · 변수 격리 설계

크로스오버 축은 실모델(resnet50·yolo26n·YOLOV5S)로 두 끝점을 잡았다 — 하지만 실모델은 연산·출력이 함께 변해 중간을 못 그린다. 전이를 그리려면 연산을 상수로 붙박고 출력만 움직여야 한다.

코어-카운트 매핑-n 1=1코어(NPU_0) · -n 4=2코어(NPU_0/1) · -n 0=3코어(NPU_ALL) — -n은 코어 ID지 개수 아님(크로스오버 축과 동일)
스테이지 측정 규약 D2H p50는 코어수 무관 불변(실측: cout=5102서 1코어 17.708 ≈ 3코어 17.710ms) — 개별 전송 시간은 고유값, 코어 경합은 지속시간이 아니라 처리량으로 나타남. 따라서 D2H는 어느 코어수로 읽어도 동일. 반면 Inference p50는 1코어(무경합)로 읽는다 — 3코어 전이 구간(cout 163–653)에선 출력 핸드오프 backpressure로 코어가 결과를 못 뱉고 대기해 Inference stage가 부풀려짐(2.7→최대 4.3ms, §3 표). 이는 추가 연산이 아니라 대기 아티팩트이므로 고정-연산 값은 1코어 Inference로 확정.
정확도 미주장 랜덤 가중치·랜덤 캘리브레이션 합성 모델 → 지연·레짐만 유효(캡스톤 init-weight 캐비앗과 동일). dxbenchmark가 입력을 합성하므로 실데이터 불필요. 이 축의 논점은 스테이지 타이밍이지 출력값이 아니다.

§4 — 전이 곡선 (헤드라인)

출력을 키우며 3코어 스케일링(3c/1c 처리량 비)이 compute-bound 3× → D2H-bound 1×로 넘어가는 곡선. 초록=near-linear(compute) · 노랑=sub-linear(전이) · 빨강=flat(D2H).

§5 — 코어 굶김 시그니처 (독립 확증)

코어 스케일링과 독립적으로, 3코어 잡 분포(어느 코어가 몇 잡 처리했나)가 같은 전이를 보인다. compute-bound면 3코어 균등, D2H-bound면 공유 링크가 코어를 굶긴다.

3코어 잡 분포 이동 (코어0 / 코어1 / 코어2, %)

균등 33/33/33(compute) → 코어2 굶김 → 코어0 독식 98/2/0(D2H) · 크로스오버 축 yolo26n 472/28/2와 동일 패턴

두 독립 축이 같은 전이를 지목 코어 스케일링(§4)과 잡 분포(§5)는 다른 관측량인데 같은 곡선을 그린다 — 균등 33/33/33(compute) → 코어2 굶김 46/45/9 → 50/48/2(전이) → 코어0 독식 93/6/0 → 98/2/0(D2H). 마지막 패턴은 크로스오버 축의 yolo26n 472/28/2(D2H-bound)와 정확히 같은 시그니처. 공유 PCIe Gen2×1 D2H 링크가 한 코어치 출력만으로 포화돼 나머지 코어를 굶긴다는 물리가 전이 전 구간에서 연속적으로 작동함을 확증.

§6 — 두 임계점 · 밴드 폭 = 코어 수

전이는 단일 임계점이 아니다. 세 스테이지(고정 연산 2.70ms · D2H = 2.456ms/MB·출력 + 0.137ms 선형)의 교차로 두 개의 임계점이 정의된다:

출력 크기 축의 세 구역 (로그 스케일)

초록=compute-bound(3코어 스케일) · 노랑=전이 밴드 · 빨강=D2H-bound · 점=측정 12점

임계점조건출력 크기무슨 일
링크-포화 개시D2H = Inference / 3≈319KB3코어가 링크 하나를 다 못 씀 → 3c/1c 스케일 붕괴 시작
단일추론 크로스오버D2H = Inference (2.70ms)≈1.05MB단일 추론마저 D2H-bound → 1코어 처리량도 급락
전이 밴드 폭 = 코어 수 (구조적) 두 임계점의 비 = Inference / (Inference/3) = 3 = 코어 수. 실측 밴드 폭 3.36×(319KB→1.05MB)가 이를 확증. 물리: N개 코어가 D2H 링크 하나를 공유하므로, 단일 추론이 아직 compute-bound여도(D2H < Inference) 세 코어의 D2H 총량은 이미 링크를 포화시킨다 — 멀티코어 처리량은 단일추론 병목의 1/N 지점에서 미리 꺾인다. 따라서 크로스오버 축이 본 "출력 크기가 레짐을 정한다"는 knife-edge가 아니라 코어 수만큼 넓은 밴드로 정밀화된다. (선형 근사는 출력 ≤1MB서 유효; 2MB↑서 D2H가 초선형이라 상단 크로스오버는 약간 압축됨 — 캐비앗 참조.)
