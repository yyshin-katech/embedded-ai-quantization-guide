Orin 온디바이스 TensorRT — 실 trtexec로 iGPU 정밀도 사다리 + DLA 오프로드 + 성능/전력

앞선 Jetson CPU 폴백 프록시는 같은 보드의 Cortex-A78AE CPU만 봤다(offload 0% 바닥값). 이제 가속기 차례다 — 통합 Ampere iGPU와 NVDLA v2. 3·5단계는 정본 pip 휠에 trtexec 실행파일이 없어 polygraphy로 대체했고(3단계), DLA는 RTX 3080에 코어가 0개라 "범위 밖"이었다. Jetson엔 둘 다 있다: 실 trtexec(TRT 10.3 JetPack)와 2개의 DLA 코어. 같은 stage3 ResNet50 ONNX로 5개 엔진(iGPU FP32/FP16/INT8 + DLA FP16/INT8)을 온디바이스 빌드하고, tegrastats로 실측 전력까지 붙였다. 결과: iGPU INT8은 1.01ms·29.7W·33.2 inf/s/W, DLA INT8은 1.28ms·15.2W·51.3 inf/s/W(iGPU 대비 전력 절반·성능/와트 1.55배, GPU를 통째로 비움). 그리고 NVDLA는 INT8 전용기 — DLA FP16은 DLA INT8보다 13.9배 느리다.

사용자 요청 실기(home 보드 Jetson AGX Orin)로 "Orin에서 할 수 있는 것" 4가지 — ① DLA INT8 · ② 실 trtexec 온디바이스 · ③ 성능/와트(tegrastats) · ④ iGPU Ampere INT8 — 를 한 번의 브링업으로 관통했다. 4가지 모두 RTX 3080 프록시로는 불가능했던 것들이다(RTX엔 DLA 0개 · 정본 pip 휠엔 trtexec 부재).

발견 1 · DLA INT8 = 성능/와트 챔피언 (item 1·3)DLA INT8은 1.28ms·15.2W·51.3 inf/s/W. iGPU INT8(1.01ms·29.7W·33.2)보다 지연은 26% 느리지만, 전력은 정확히 절반(0.51×)이고 성능/와트는 1.55배다. 게다가 DLA가 도는 동안 GPU는 통째로 비어(GR3D 16%) 다른 일을 시킬 수 있다. "가속기 오프로드 = 지연을 조금 내주고 전력·병렬성을 크게 번다"를 실기 정량으로 확인.
발견 2 · 실 trtexec가 3·5단계 공백을 메움 (item 2)3·5단계는 정본 pip 휠에 trtexec가 없어 polygraphy Python API로 우회했다. Jetson엔 /usr/src/tensorrt/bin/trtexec(TRT 10.3, JetPack)가 실존 → 문서의 원래 trtexec --int8/--fp16/--useDLACore 명령을 그대로 관통. 5개 엔진 전부 exit 0 빌드.
발견 3 · NVDLA는 INT8 전용기 (item 1)DLA FP16 17.73ms vs DLA INT8 1.28ms = 13.9배 차이인데 레이어 배치는 동일(둘 다 DLA-후보 2/2 오프로드 = conv 백본 120층 + fc, tail 2층만 GPU 폴백). 차이는 순수 데이터패스 — NVDLA v2의 INT8 MAC 처리량이 FP16 대비 압도적. DLA에선 INT8이 선택이 아니라 필수(iGPU는 FP16≈INT8인 것과 정반대).
발견 4 · 작은 Ampere iGPU는 INT8≈FP16 (item 4)iGPU INT8 1.013ms는 FP16 1.029ms보다 1.6%밖에 안 빠르다(비율 0.984). RTX 3080(3단계)에선 INT8이 FP16보다 8% 빨랐다 — Orin의 작은 iGPU(2048 CUDA코어)는 이 모델에서 더 강하게 launch/메모리 바운드라 INT8 연산 이득이 거의 사라진다. 정밀도 이득도 GPU 크기에 의존.
CAVEAT 모든 지연은 trtexec GPU-compute median(디바이스 event-timed, H2D/D2H 제외) · batch1 · MAXN 기준. 전력은 tegrastats 보드 총합(GPU_SOC+CPU_CV+SYS_5V0, 부하 중 중앙값). iGPU INT8은 stage3 명시적 QDQ(실 스케일)지만 DLA INT8은 trtexec --int8 암묵 캘리브(자동 레인지) — 지연·전력은 유효, 정확도는 주장하지 않음(정확도는 stage3 RTX·stage4 CPU 프록시에서 별도 확립). 절대값은 상대 관계로만 읽을 것.

지연 사다리 — batch1, 디바이스 event-timed (낮을수록 빠름)

막대폭 = 지연 ms × 288.9px. DLA INT8도 함께(§4). DLA FP16(17.73ms)은 척도 밖이라 제외.

ITEM 2 — 실 trtexec 5개 엔진 전부 실 trtexec 바이너리로 빌드(exit 0). 3·5단계에서 "정본 pip 휠에 trtexec 부재 → polygraphy로 대체"라고 기록했던 그 명령들(trtexec --onnx=… --int8/--fp16 --saveEngine=…)이 Jetson에선 원문 그대로 동작한다. 플래그 1건 정정: 이 트림(TRT 10.3)의 빌드전용 플래그는 --buildOnly가 아니라 --skipInference(전자는 Unknown option).
ITEM 4 — iGPU INT8 ≈ FP16 이 작은 Ampere iGPU에선 INT8이 FP16보다 1.6%밖에 안 빠르다(1.0132 / 1.0293 = 0.984). 3단계 RTX 3080은 INT8/FP16 = 0.927(INT8이 8% 빨랐음). batch1 ResNet50은 연산량보다 커널 launch·메모리 대역에 묶이는데, iGPU는 그 바운드가 더 세서 INT8의 연산 이득이 거의 상쇄된다. 단, INT8 엔진은 여전히 최소 크기(26 MiB, FP32의 27%)이고 전력에선 확실히 이긴다(§5).

참고 — 3단계 RTX 3080(polygraphy, 동일 event-timed 방법론): FP32 1.6615 → FP16 0.8459(×1.96) → INT8 0.7843ms(×2.12). Jetson iGPU는 FP32에서 1.17×, INT8에서 1.29× 느리다 — 2048 vs 8704 CUDA 코어 격차치고 batch1에선 의외로 근접(지연 바운드라 코어 수 격차가 덜 드러남). 다른 GPU라 절대 비교는 참고용.

§4 — DLA 오프로드 (item 1)

RTX 3080은 DLA 코어가 0개라 3단계에서 "DLA 범위 밖"이었다. Orin엔 NVDLA v2 2개가 있다. --useDLACore=0 --allowGPUFallback로 DLA0에 올리고, --verbose로 레이어 배치를, tegrastats GR3D로 오프로드를 검증했다.

엔진백엔드지연Throughputsteady 전력GR3D(GPU 3D)

FP16DLA017.7344 ms56.3 qps15.69 W3%
INT8(대조)iGPU1.0132 ms984.7 qps29.70 W95%
오프로드 확증 (behavioral) DLA 실행 중 GR3D(GPU-3D 사용률)가 3%(FP16)·16%(INT8)로 붕괴한다 — iGPU 엔진은 95~98%. 즉 연산이 GPU가 아니라 DLA에서 실제로 돌고 GPU는 비어 있다. 전력에서도 DLA 런의 VDD_GPU_SOC는 5.6~6.0W로, iGPU 런의 21.8~32.7W보다 극적으로 낮다(SOC 레일이 DLA를 먹여도 GPU 코어가 안 돎). "가속기 오프로드"가 말이 아니라 계측으로 확인됨.
레이어 배치 (--verbose) DLA INT8·FP16 둘 다 동일: Number of DLA node candidates offloaded: 2 out of 2. DLA 서브그래프는 2개 ForeignNode — ① 전체 conv 백본 /conv1/Conv‥/layer4.2/relu_2(120개 DLA 층), ② /fc/Gemm + bias(FC도 DLA에 올라감). GPU 폴백은 compute 2층뿐 — GlobalAveragePool(REDUCE→POOLING, "DLA cores do not support AVG Reduce")과 flatten SHUFFLE. 즉 배치는 같고 정밀도만 다른데 지연이 13.9× 벌어진다.
함정 — DLA FP16 DLA FP16 17.73ms는 DLA INT8 1.28ms의 13.9배. 배치가 동일하므로 원인은 순수 NVDLA 데이터패스 — v2의 INT8 MAC 처리량이 FP16 대비 압도적으로 높다. DLA에 올릴 거면 반드시 INT8. FP16으로 DLA를 쓰면 iGPU FP32(1.94ms)보다도 9배 느린 최악의 조합이 된다(단 전력은 15.7W로 낮음 → 극저전력·저처리량 니치 외엔 쓸 이유 없음).
ITEM 1 판정 DLA INT8은 실사용 가능: 1.28ms(iGPU INT8의 1.26×)에 전력 절반·GPU 프리. ResNet50 같은 깔끔한 CNN은 tail 2층 빼고 전부 DLA에 얹힌다. RTX 3080에서 못 했던 축을 실 보드로 채움.

성능/와트 — inf/s/W (높을수록 효율적)

막대폭 = inf/s/W × 11.5px. DLA INT8이 iGPU INT8의 1.55배.

전력 스케일링 iGPU에서 정밀도를 낮출수록 전력도 단조 감소: FP32 42.3W → FP16 36.2W → INT8 29.7W. 더 빠르면서 더 적게 먹으니 성능/와트는 12.2 → 26.8 → 33.2로 개선. DLA INT8은 이 곡선 밖에서 15.2W·51.3로 따로 논다.
전원 공급장치(PSU) — 실측 답 ResNet50 batch1 추론 중 보드 실측 피크 = 42.4W(iGPU FP32), 유휴 7.6W. 이건 단일 모델·batch1 워크로드 기준이고, 64GB 모듈의 설계 상한은 60W(MAXN)라 배치 확대·iGPU+DLA+CPU 동시부하면 그쪽으로 오른다. 따라서 동봉 19V 배럴잭 어댑터(정격이 60W 위에 여유)로 충분하며, 서드파티라면 19V·90W급 권장. PSU가 빠듯하면 nvpmodel로 30W/15W 캡 가능(설정은 sudo 필요).
ITEM 3 판정 DLA INT8이 성능/와트 챔피언(51.3). 지연 최우선이면 iGPU INT8(1.01ms), 전력·배터리·GPU 확보가 목적이면 DLA INT8(전력 절반, 지연 26%만 손해). 자동차/로봇 다중 모델 배치에서 DLA에 상시 CNN을 얹고 GPU를 무거운 헤드에 남기는 전형적 분업이 수치로 정당화됨.

§6 — 판정·산출물

DONE item 1 · DLA INT8

DONE item 3 · 성능/와트 (tegrastats)
