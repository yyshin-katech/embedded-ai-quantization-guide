0 · 환경 준비

문서 3장은 레벨별로 conda create -n ladder-litert/ladder-onnx/ladder-et 격리를 지정하지만, 이 머신엔 conda가 없다 (Stage 0 설치 때와 동일한 상황). Stage 0의 선례를 따라 venv로 대체하고, Lv.3은 이미 검증된 ~/emb-ai를 재사용한다.

bash
$ which conda
(출력 없음 — conda 미설치, exit 1)

$ mkdir -p ~/ladder-work/{lv1,lv2,lv3,lv4,aihub}
$ python3 -m venv ~/ladder-litert   # Lv.2용
$ python3 -m venv ~/ladder-et       # Lv.4 + Qualcomm AI Hub용 (문서: "qai-hub도 여기서")
✓ venv 2개 생성 완료. Lv.3은 새로 만들지 않고 기존 ~/emb-ai 재사용 (torch/onnxruntime-gpu/tensorrt 스택이 이미 실측 검증된 상태)
계정 필요 구간 처리 정책 Lv.1(Edge Impulse Studio 웹 워크플로)과 Qualcomm AI Hub(실단말 프로파일링)는 실제 계정 가입·API 토큰이 필요해 이 세션에서 끝까지 실행할 수 없다. 대신 계정 없이 가능한 모든 것(CLI/패키지 설치, --help/--version, 실제 인증 실패 에러 캡처)까지는 실행하고, 그 이후는 명시적으로 "계정 필요로 실행 불가"로 표기한다.

함정 · 2건 ① opset 요청 무시: opset_version=17로 명시해도 torch 2.11의 dynamo 기반 exporter가 내부적으로 opset 18로 내보낸 뒤 17로 다운그레이드하려다 실패 — catch되어 스크립트는 성공한 것처럼 끝나지만 실제 파일은 opset 18이다. (다행히 ir_version 10 ≤ ORT 1.23.2의 상한 11이라 로드/실행엔 문제 없음.)
② 파일 분리: print("saved resnet18.onnx")는 파일 하나만 저장된 것처럼 보이지만, 실제로는 그래프(.onnx, 91.7KB)와 외부 가중치(.onnx.data, 44.6MB)로 나뉜다. 배포 시 이 둘을 항상 같이 옮겨야 한다 — 하나만 복사하면 조용히 깨진다.

bash · 최초 실행 (버그 있는 상태)
$ python lv3_bench.py

CUDA      active=CUDAExecutionProvider      p50= 1.4x  p95=...  ms
2026-07-31 ... [E:onnxruntime:Default, provider_bridge_ort.cc] ... libnvinfer.so.10: cannot open shared object file: No such file or directory
Failed to create TensorrtExecutionProvider. ... falling back to other providers

함정 · 무음 fallback ort.get_available_providers()엔 TensorrtExecutionProvider가 정상적으로 나열되어 있었지만, 실제 InferenceSession 생성 시점엔 libnvinfer.so.10을 동적 로더가 못 찾아 조용히 CPU로 폴백하고 있었다. 에러 로그가 stderr에 찍히긴 하지만, 눈여겨보지 않으면 "TensorRT 벤치를 돌렸다"고 착각하기 쉬운 상황 — 실제 활성 프로바이더는 sess.get_providers()[0]으로 반드시 확인해야 한다.

문서 주장 검증됨 정확히 문서가 설명한 실패 모드 그대로 재현됐다 — data-dependent 분기는 torch.export 단계에서 명확한 에러로 걸러진다 (조용히 틀린 그래프를 만들지 않음).
