DEEPX DX-M1 — 검출(YOLO26n) INT8 정확도 + NMS-fold 레짐

정확도 축(분류 ResNet50)과 크로스오버 축(host-bound↔NPU-bound)을 하나의 검출 모델로 잇는다. 같은 yolo26n 640×640으로 COCO val2017 mAP(정확도)와 온보드 스테이지 프로파일(레짐)을 동시에 측정 → ① 검출 INT8은 무손실급: FP32 0.448 → COCO-캘리브 INT8 0.439, 순수 양자화 −0.009(−2.0%), 캘리브 도메인 차 +0.0033(노이즈 내) — 분류 축(native 0.766≈FP32 0.762)의 검출판 확증. ② NMS-fold는 레짐을 못 바꾼다: [1,300,6] "end2end" export도 dx_com은 raw 헤드(6 conv 출력, 2.82MB)에서 그래프를 자르고 decode·NMS를 호스트에서 돈다 → D2H가 여전히 2.82MB/프레임 → D2H-bound(D2H 21.8ms ≫ 연산 7.3ms, 코어 잡 473/27/2) → 크로스오버 raw-head yolo26n(472/28/2)과 동일 → 크로스오버 결론을 확증·심화.

2 · NMS-fold 레짐 — "end2end" export도 레짐을 못 바꾼다

가설: [1,300,6]로 NMS가 접힌 "end2end" export는 출력을 2.82MB→7.2KB로 392× 줄여 D2H-bound→compute-bound로 뒤집을 것이다. 실측은 반증.

결정적 관찰 — dxbenchmark로 본 "end2end" .dxnn(prebuilt A와 내 컴파일 B 둘 다)의 NPU 출력 텐서는 여전히 6개 raw conv 헤드(one2one_cv2/cv3 @80/40/20, 합 2,822,400 B):

dx_engine.run()가 돌려주는 [1,300,6]은 호스트(CPU)에서 decode+NMS를 돌려 만든 것 — .dxnn 패키지에 번들된 호스트 후처리다. dx_com은 NMS를 NPU에 못 접는다 → 매 프레임 2.82MB raw 헤드가 PCIe를 건넌다.

반증된 가설 NMS-folding은 DX-M1에서 레짐을 못 바꾼다. "end2end" [1,300,6] export는 NPU 상의 축소가 아니라 호스트 편의일 뿐 — dx_com이 raw 멀티스케일 헤드에서 그래프를 자르고 decode·NMS를 CPU로 내리기 때문. 그래서 raw-head export든 end2end export든 NPU→호스트 D2H는 동일한 2.82MB → 둘 다 D2H-bound(코어 잡 분포 473/27/2 vs 472/28/2로 동일 시그니처). 이는 크로스오버 축의 결론("yolo26n은 출력 크기 탓에 D2H-bound")을 반증이 아니라 심화한다 — D2H 병목은 export 선택의 우연이 아니라 구조적(이 툴체인에선 NMS를 접어 출력을 줄이는 길 자체가 없음).

3 · 양자화 격리 방법 (분류 축 top-1 방법의 검출판)

모델yolo26n(ultralytics) 640×640 letterbox(pad114 중앙), 출력 output0 [1,300,6] = [x1,y1,x2,y2,score,class] xyxy@640, class 0-79, NMS 그래프 내
평가셋COCO val2017 정렬 첫 500장(결정론적) → 640 letterbox → 하나의 uint8 npy로 스택, FP32(x86 ORT)·NPU(Pi dx_engine)가 같은 배열을 읽음 → letterbox 기하 비트 동일(전처리 confound 0)
디코드공유 모듈 yolo_det_common.decode() — 두 백엔드가 같은 [1,300,6]을 같은 코드로 언-letterbox → mAP 차 = 양자화 only
FP32 refyolo26n.onnx(=Option B 컴파일 입력과 동일 weight) · (u8/255).transpose RGB NCHW · ORT
Option A벤더 쇼케이스 prebuilt .dxnn — 블랙박스 캘리브(DEEPX 파이프라인)
Option B내 dxcom -c yolo_coco_cfg.json 컴파일 — 동일 stock onnx + 100장 in-domain COCO 캘리브(val2017[500:600], eval[0:500]과 disjoint)
함정 — yolo 캘리브는 ÷255만 (ImageNet norm 금지) 정확도 축 ResNet50 config는 div 255 다음에 ImageNet normalize(mean/std)를 접었다. yolo는 ÷255만 쓰므로 Option B config에서 normalize 블록을 반드시 제거(넣으면 캘리브 통계가 어긋남). 접힘=Div·Transpose, 스킵=convertColor·expandDim → 런타임 입력 uint8 NHWC RGB(caller가 RGB 공급, 분류 축과 동일 계약). img0 cat_ids가 거실 클래스(person/chair/tv…)로 나와 RGB 경험 확증.
Option B 컴파일 (AI-LAP dxcom-venv, x86) + Pi 추론 + 채점
