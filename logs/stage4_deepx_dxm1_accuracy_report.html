DEEPX DX-M1 — 정확도 축: 외부 QDQ 거부 · CPU↔NPU 경로 의존

DX-M1 벤치(지연·처리량·전력)는 캐비앗 #4로 "정확도 미측정(prebuilt·라벨셋 부재)" 을 남겼다. 이 후속 축이 그걸 닫는다. 벤치는 라벨셋 없는 yolo26n이었으므로, 정확도가 필요한 이번엔 3·5단계와 공유하는 ResNet50 + ImageNet 1000장 번들로 스코프를 옮겨 실제 top-1을 라벨과 대조한다. 두 질문에 답한다 — (a) DX-M1은 외부에서 만든 QDQ scale을 존중하나, 아니면 Qualcomm Hexagon HTP처럼 무시해 붕괴시키나? (b) 같은 A76이 CPU 폴백 프록시이자 DX-M1 호스트이므로 같은 보드·같은 번들로 NPU INT8 ↔ CPU FP32/INT8 예측을 이미지 단위로 뺄셈 — "정수커널 경로의존"(3·4단계 실)을 실 벤더-NPU로 확장한다.

2026-08-31 Raspberry Pi 5 (A76) + DEEPX DX-M1 dx_com 2.4.0 · dx_engine 3.4.2 ResNet50 · ImageNet 1000장 · batch1 NPU native INT8 top-1 0.7660 (붕괴 없음) 외부 QDQ 컴파일 하드 거부 CPU↔NPU 939/1000 (경로의존) cross-run 1000/1000 (ORT 1.28↔1.29)

판정 (a) 외부 QDQ = 컴파일 단계 하드 거부 (Qualcomm과 실패양식 정반대)

외부 ORT-QDQ(resnet50_int8_qdq.onnx)를 dx_com에 넣으면 컴파일이 죽는다 — weight/bias의 DequantizeLinear 분기가 106 isolated node(s)로 걸려 GraphStructureError, 일반 InternalError: contact DEEPX로 래핑. 산출물이 없다. Qualcomm HTP는 같은 외부 QDQ를 조용히 통과시킨 뒤 런타임 top-1을 0.75→0.005로 붕괴시켰다. 두 벤더 공통 근본 = NPU가 양자화를 소유(BYO-QDQ 미지원)이나, DEEPX는 "조용히 깨진 모델을 배포"할 수 없다는 점에서 안전한 실패다.

판정 (b) 정수커널 경로 의존이 실 vendor-NPU까지 확장 — 단조 1000→961→939

다름의 원천이 하나씩 더해질수록 일치율이 단조 감소: 같은 커널+scale(stage4 Jetson↔Pi5) 1000 → 같은 scale·다른 커널(stage3 CPU↔iGPU) 961 → 다른 커널+scale+전처리 위치(여기 DX-M1 CPU↔NPU) 939. 939가 stage3의 961보다 낮은 것은 (a) 때문에 scale을 고정할 수 없어서다(NPU가 자체 native scale 강제). 헤드라인 61장 불일치 = NPU 정답 26 · MLAS 정답 10 · 둘다 오답 25 → net +16 = top-1 0.7660−0.7500 = +16/1000(산술 정합).

dx_com은 전처리를 항상 그래프에 접는다. 런타임 입력은 uint8 NHWC [1,224,224,3](get_input_size=150528), 출력 logits [1,1000] f32. 컴파일 로그 원문:

§3 — (a) 외부 QDQ 하드 거부 (Qualcomm 대조)

§4 — native top-1 사다리 (같은 1000장 번들)

native PTQ INT8은 FP32 대비 무손실급 — 붕괴가 없다. (a)의 거부 때문에 유일한 INT8 경로는 이 native뿐이다.

on-device top-1 (ResNet50 · ImageNet 1000장 · batch1)

막대 폭 = top-1 × 600 · SSOT accuracy_summary.json

주의 npu_native 0.7660 > cpu_fp32 0.7620은 "이김"이 아니다. +0.4%p(=+4/1000)는 1000장 서브셋 노이즈 내(1단계 함정 0). 결론은 "붕괴 없음·무손실급"이지 "FP32 초과"가 아니다. 절대 top-1은 1000장 서브셋이라 3·5단계 5000장 RTX와 비교 불가 — 같은 번들 상대 관계만 유효.

§5 — (b) CPU↔NPU 경로 의존 (헤드라인)

불일치 장수 = 경로 차이의 크기. 다름의 원천(커널·scale·전처리 위치)이 하나씩 더해질수록 단조 증가한다.

예측 불일치 장수 (n=1000) — 경로 차이가 커질수록 단조 증가

막대 폭 = 불일치 장수 × 8 · 값이 작을수록 두 경로가 더 같음

전체 일치 다리(SSOT):

일치 다리무엇이 다른가agree/1000
(stage4) Jetson↔Pi5없음 (같은 MLAS SDOT)1000
(stage3) CPU↔iGPU (TRT vs MLAS)커널만 (같은 QDQ scale)961
(여기) CPU↔NPU (MLAS vs DX-M1)커널 + scale + 전처리 위치939
cpu_int8 vs cpu_fp32 (동일 A76)양자화만 (같은 커널족)950
npu_int8 vs cpu_fp32양자화+커널+전처리969

헤드라인 61장(=1000−939) 불일치 분해 — 누가 맞았나:

구분장수기여
NPU 정답 · MLAS 오답26NPU +26
MLAS 정답 · NPU 오답10NPU −10
둘다 오답25중립
합계61net +16 = 0.7660−0.7500
왜 939 < 961인가 stage3의 961은 같은 QDQ scale(rn50_gpu_int8.plan이 CPU 프록시와 같은 resnet50_int8_qdq.onnx에서 빌드)이라 유일 변수가 커널이었다. 여기서는 (a) 때문에 scale을 고정할 수 없다 — NPU가 자체 native PTQ scale을 강제하므로 커널+scale+전처리 위치가 동시에 다르다. 따라서 939는 순수 커널-only 상한이 아니라 3중 confound이며, "경로가 다르면 ~94–96% 대역"이라는 결론과 정합한다.
cross-run 재현성 이 세션 CPU arm(ORT 1.29.0) vs 커밋된 stage4 Pi5 프록시(ORT 1.28.0), 같은 A76·같은 번들: cpu_fp32 1000/1000 · cpu_int8 1000/1000 비트 동일. → 번들이 이미지 단위로 동일함을 md5 외에 예측으로도 확인 + MLAS SDOT 정수커널이 ORT 1.28→1.29에서 불변(같은 커널=100%, 경로의존 스레드 정합).
