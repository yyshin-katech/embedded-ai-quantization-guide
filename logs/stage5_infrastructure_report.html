문서 하네스를 실행 가능 형태로 완성하고 실측으로 8건을 정정했다. 검증 인스턴스는 ResNet50/ImageNet(3단계 자산) — BEVFormer INT8은 2단계에서 유효 export 경로 없음(포크 필요)으로 범위 밖.

정정 1 · 🔴 pycuda 부재문서 §4-3 trt.py는 import pycuda.driver + mem_alloc/memcpy_htod/execute_async_v3/Stream인데 정본 venv에 pycuda가 없다(ImportError). → polygraphy TrtRunner로 대체(디바이스 버퍼·H2D/D2H·sync 내부 처리). 3단계 trtexec 부재와 같은 결 — 정본 pip 휠엔 NVIDIA C++ 계열이 빠져 있다.
정정 2 · 🔴 INT8 캘리브레이터 주석§4-3 L367–369가 config.int8_calibrator = ...를 "지면상 생략" 주석 처리 → 스케일 없는 무의미 엔진. 3단계 t04와 동일 IInt8EntropyCalibrator2 실제 배선. 결과 top-1 0.768(=t04 일치).
정정 3 · 🟡 device_memory_size§4-3 L416 engine.device_memory_size는 TRT 10.x deprecated → device_memory_size_v2(실측 전 셀 v2가 먹힘). 값 의미 주의: 실행컨텍스트 scratch(8.4→3.9→1.7MB)이지 엔진파일/가중치 크기 아님.
정정 4 · 🔴 data.py 미제공§4-5 L591 from data import Loader, Evaluator인데 data.py가 없다(데이터층은 프로젝트마다 달라 문서가 비운 자리) → ResNet50/ImageNet 데이터층 제공. FP32 top-1 0.7688=공개값·3단계 일치로 정렬 검증.
정정 5 · 🔴 zero-copy 무음오답§4-3 measure()의 preds=[self.run(x) for ...]가 polygraphy zero-copy 러너와 만나면 5,000개가 마지막 추론 하나를 가리켜 acc 0.0014(=1/1000). pycuda 원안은 매 호출 새 버퍼라 안전 — 치환의 부작용. 처방 .run(x).copy() → 0.7688. (§4)
정정 6 · 🟡 pivot이 회색행 삭제§4-6 pivot_table의 dropna=True(기본)가 stub NaN 행을 조용히 버려 §5-1 "회색행 보존" 원칙을 자기위반. 실행해 표를 봐야만 드러남. 처방 dropna=False(+HTML na_rep="보드필요"). CSV는 원래도 6행 보존. (§5)
정정 7 · 🟢 EXPLICIT_BATCH§4-3 L349 "명시해도 무방" → 10.16 실측: 명시 시 DeprecationWarning("Implicit batch ... removed"), 무인자 create_network()가 이미 explicit. 정밀화(반전 아님). polygraphy 경로는 우회.
정정 8 · 🟢 pytest-regressions "v3.0+"문서 5곳의 "v3.0+ 권장"은 사실오류 — PyPI 최신 2.11.0(0.1.0~2.11.0, v3.x 부재). dataframe_regression fixture는 2.11.0에 존재 → 코드는 동작, 버전 표기만 틀림.
캐비앗(먼저) 절대 지연·top-1·scratch mem은 CUDA/RTX 3080 · polygraphy wall-clock · 배치1 · implicit 캘리브 · 5,000장 서브셋 기준이다. 서브셋 top-1은 공개 50k보다 부풀려질 수 있다(1단계 함정 0). 유효 결론은 상대 관계 — 배율(×1.80/×2.13), 회귀 델타, 회색행 유무 — 이며 절대값의 문헌 비교는 하지 않는다.

재현 ✓ INT8 ×2.13 · top-1 0.768 = 3단계 t04 일치

FP16은 top-1 사실상 동일(0.7686)에 ×1.80, INT8은 ×2.13에 top-1 0.768(=3단계 t04 implicit 캘리브 0.768과 정확히 일치). FP32 0.7688도 공개값·3단계와 일치 → 데이터층·라벨정렬·전처리 전부 올바름. scratch mem 8.4→3.9→1.7MB 단조 감소.

방법론 절대 지연이 3단계(event-timed last_inference_time, FP32 1.6615ms)보다 높은 건 하네스 _timeit이 wall-clock(perf_counter)이라 H2D/D2H·Python 오버헤드를 포함하기 때문. 그래서 배율도 압축(×1.80/×2.13 vs 3단계 ×1.96/×2.12) — 정밀도 무관 고정 오버헤드가 분모에 상수로 얹혀 배수를 줄인다. 측정계 의존, 상대 관계만 유효.

§4 — 정정 5: zero-copy 러너의 무음 오답 (핵심 발견)

문서 measure()의 정확도 루프 preds=[self.run(x) for x in loader.eval_set()]는 pycuda 원안에선 안전하다(매 호출 np.empty 새 버퍼). 그런데 정정 1로 run()을 polygraphy TrtRunner.infer로 바꾸면 — 러너가 호스트 출력버퍼를 재사용해 반환이 그 버퍼의 view가 된다. 리스트에 모으면 5,000개 전부가 마지막 추론을 가리킨다.

FP32 top-1 — 같은 엔진·같은 데이터, .copy() 유무만 다름

막대 길이 ∝ top-1 (스케일 600px/1.0). 아래 막대가 무음 오답의 실측.

교훈 "추상 measure() 계약(preds를 모은 뒤 평가)"이 zero-copy 러너와 만나면 무음 오답이 된다. exit 0, 예외 0, 로그 정상 — 오직 숫자만 틀린다. 버퍼 소유권이 바뀌는 치환(pycuda→polygraphy)에선 반드시 즉시 .copy()하거나 루프 안에서 소비하라(3단계 t3_common.evaluate_top1은 루프 안 즉시 argmax로 이 함정을 원천 회피했다).

자기모순 문서 §5-1은 정반대를 명령한다: "회색(보드필요) 행도 매트릭스에 남긴다 → '아직 측정 못 함'과 '측정했더니 나쁨'은 다르다. 빈칸이 아니라 명시적 '보드필요'가 정직한 보고다." 즉 §4-6 코드가 §5-1 원칙을 스스로 위반한다 — 코드만 읽으면 안 보이고 실행해 표를 봐야 드러난다. 처방: 모든 pivot dropna=False + HTML na_rep="보드필요". CSV(long-form)는 원래도 6행 전부 보존하므로 회귀 baseline·게이트엔 영향 없다(사람이 읽는 표에서만 정직성이 훼손됐다).

§6 — 회귀 게이트 실증 (통과 + 의도적 실패)

두 층 이중화 — (A) 임계값(map 1%p·latency ×1.10) + (B) pytest-regressions 골든. baseline은 cp report/matrix.csv tests/baseline_matrix.csv. 게이트가 실제 회귀를 잡는지를 주입으로 증명한다.

pytest — 정상 → 의도적 회귀 주입 → 복원
# 정상 (골든 존재)
$ pytest tests/ -q
... 3 passed in 0.19s

# 의도적 회귀 주입: int8 acc 0.768→0.740(−2.8%p), latency 0.8628→1.10(×1.27)

FAILED test_matrix_matches_golden   # diff latency 0.2372 · acc 0.028
3 failed in 0.26s

# 원본 복원
$ pytest tests/ -q
... 3 passed in 0.19s

실증 ✓ 두 층이 실제 회귀를 잡는다

임계값 층(A)은 정책("얼마나 나빠지면 실패")을, 골든 층(B)은 감시("숫자가 조용히 바뀌면 눈에 띄게")를 담당한다. 주입한 회귀를 세 테스트가 모두 포착하고, 복원 시 전부 통과 — 게이트가 장식이 아니라 작동함을 확인.

§7 — 판정 · 산출물

완성 ✓ 하네스 골격은 건전, 실행 가능 형태로 완주

ABC 인터페이스·순회 러너·매트릭스·회귀 게이트 전부 실동작. 문서가 비운 두 자리(pycuda I/O·data.py)를 정본 스택(polygraphy·ImageNet)으로 채워 6셀 매트릭스를 뽑았다.

정정 ✓ 무음 오답 2건이 핵심

정정 5(zero-copy eval)·6(pivot dropna)은 exit 0으로 통과하며 결과만 조용히 틀린다. 전자는 정확도를 우연 수준으로 붕괴, 후자는 §5-1 정직성 원칙을 위반. 실행해야만 드러나는 종류라 실기 검증의 값어치가 여기 있다.

정직화 ✓ SoC 3종은 범위 밖 명시

tidl/qnn/drpai는 실물·SDK 없음 → stub 회색 셀. 하네스가 죽지 않고 '보드필요'로 봉인됨을 검증(4단계 과제). BEVFormer INT8·MLflow도 범위 밖(2단계 결론·선택).
